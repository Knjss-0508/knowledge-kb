# 模型训练样本从零收集执行方案

> 版本：v0.1 评审稿  
> 日期：2026-09-14  
> 适用范围：候选价值复核、知识转写、推荐回复、待发布审核和模型训练  
> 当前目标：从零开始积累可信样本，暂不使用口径不统一的历史修改数据

---

## 1. 先说结论

这套方案可以执行，建议先从“小规模人工试运行”开始，不要一上来就让模型自动训练或自动通过。

完整过程是：

```text
新候选进入候选价值复核
        ↓
模型保留初标、置信度和原始生成内容
        ↓
人工按照统一口径完成复核和修改
        ↓
系统保存模型原稿、人工结论、人工终稿和修改原因
        ↓
通过样本质检后，成为可信人工真值
        ↓
分别进入训练集、验证集或长期测试集
        ↓
训练候选模型，并与当前模型对比
        ↓
只在验证达标后灰度使用
        ↓
按置信度区间和真实准确性决定人工全检、抽检或前置复核直接通过
```

这里的“候选价值复核直接通过”只表示：

> 跳过候选价值复核的人工操作，进入“知识库管理—待发布审核队列”；不代表知识已经正式发布。

发布审核仍然是独立门禁，模型不得绕过。

---

## 2. 为什么要从零收集

以前线上虽然有人工修改，但目前存在以下问题：

- 修改口径可能比较主观；
- 不清楚修改发生在哪个页面和字段；
- 不一定能找到修改前内容；
- 不一定记录修改原因；
- 不一定能确认最终是否通过发布审核；
- 不一定能区分总部标准和业务沉淀知识；
- 无法证明所有历史修改都可以作为正确答案。

因此，本方案把历史数据暂时放在“待清洗历史数据池”，不作为第一版模型的正式训练真值。

从方案启用日期起产生的新数据，按照统一字段、统一流程和统一标注口径收集。等新流程稳定后，再单独评估历史数据是否值得清洗补录。

---

## 3. 本次到底要收集什么

一条候选记录可能同时产生三种不同用途的样本，不能只用一个“是否进入训练样本”标签概括。

### 3.1 候选价值判断样本

用于训练模型判断：

- 主题属于什么知识分类；
- 是否有持续复用价值；
- 当前应当采取什么知识处理动作；
- 是否存在必须人工复核的风险。

这是第一阶段最优先收集、也最容易形成可靠闭环的样本。

### 3.2 知识内容修订样本

用于改善模型生成的：

- 主标题；
- 副标题；
- 知识正文；
- 推荐回复；
- 适用范围；
- 关联标准。

这类样本必须同时保存“模型原稿”和“人工终稿”。只有一个最终结果，没有修改前内容，无法判断模型错在哪里，也不适合直接作为高质量生成训练样本。

### 3.3 发布结果样本

用于记录候选进入待发布审核后的最终结果：

- 发布审核通过；
- 修改后通过；
- 退回补充；
- 驳回；
- 暂缓发布。

发布结果是训练样本质量的重要佐证，但发布审核通过不等于所有字段都可以直接用于训练。仍需经过样本质检和数据集分配。

---

## 4. 必须统一的业务术语

| 术语 | 准确定义 |
|---|---|
| 模型初标 | 模型对主题分类、沉淀价值、内容质量等作出的原始判断 |
| 候选价值复核 | 判断候选是否有沉淀价值、采取什么处理动作的业务审核环节 |
| 待发布审核 | 候选价值复核通过后，在知识库管理中等待最终发布审核的状态 |
| 训练候选样本 | 人工已经处理，但尚未通过样本质检的数据 |
| 可信人工真值 | 按统一口径复核、字段完整、冲突已处理、可用于评估模型的数据 |
| 训练集 | 允许模型学习的数据 |
| 验证集 | 训练过程中用于选择模型和参数的数据，不参与直接训练 |
| 长期测试集 | 用于比较新旧模型的数据，训练人员不得把答案用于训练 |
| 自动通过 | 跳过当前候选价值人工复核，进入待发布审核，不是正式发布 |
| 总部标准 | 业务侧只能引用、无权限直接修改的总部知识 |
| 业务沉淀知识 | 业务侧有权限新增或维护的知识，包括总部标准的本地补充 |

---

## 5. 人工标注口径

人工复核不要只回答“值得”或“不值得”，至少拆成下面几个维度。

### 5.1 维度一：是否有复用价值

| 标签 | 使用条件 |
|---|---|
| 有复用价值 | 能解决重复出现的问题，存在稳定规则、边界、例外、步骤或可复用案例 |
| 无复用价值 | 仅为一次性沟通、无稳定结论、个人表述、重复已有知识且没有新增内容 |
| 暂无法判断 | 内容可能有价值，但证据不足、来源冲突或需要业务确认 |

### 5.2 维度二：知识处理动作

| 处理动作 | 使用条件 |
|---|---|
| 新增业务沉淀知识 | 没有现成业务知识；或者是对总部标准的本地执行补充、业务细则、案例或适用差异 |
| 补充或更新已有业务知识 | 已有知识属于业务侧，且业务侧拥有修改权限 |
| 待补充证据或待业务确认 | 有潜在价值，但依据、范围、事实或权限尚未确认 |
| 不沉淀 | 没有持续复用价值，或已有知识已经完整覆盖且没有新增信息 |

### 5.3 总部标准的特殊规则

总部标准无权限修改，必须遵守以下规则：

```text
发现总部标准需要本地业务补充
        ↓
处理动作为“新增业务沉淀知识”
        ↓
新知识关联总部标准
        ↓
写清本地适用范围、执行细则或补充场景
        ↓
不得覆盖、改写或替换总部标准正文
```

具体口径：

| 场景 | 正确处理 |
|---|---|
| 总部标准正确，本地有额外执行细则 | 新增业务沉淀知识，并关联总部标准 |
| 总部标准正确，本地有特殊案例或适用差异 | 新增业务沉淀知识，写清适用范围并关联总部标准 |
| 怀疑总部标准错误、过期或缺失 | 标记“总部标准异常待反馈”，不得直接修改 |
| 本地经验与总部标准冲突 | 必须人工升级确认，不得自动沉淀为覆盖总部标准的新规则 |
| 已有业务知识需要补充 | 补充或更新已有业务知识 |

“总部标准异常待反馈”建议作为风险标记，不替代四种知识处理动作。

### 5.4 维度三：模型判断是否正确

人工必须明确记录：

- 模型判断完全正确；
- 模型结论正确但标签或边界不完整；
- 模型判断错误；
- 因证据不足无法评价模型。

这个字段用于统计模型在每个置信度区间的真实准确性。

### 5.5 维度四：正文质量

| 标签 | 定义 |
|---|---|
| 可直接使用 | 事实、结构、范围、步骤和表达均可直接进入后续审核 |
| 轻微修改 | 核心结论正确，只修改措辞、格式或少量补充 |
| 需要重写 | 核心结构、规则、适用范围或关键步骤存在明显问题 |
| 无法形成知识 | 原始证据不足或该内容本身不应形成知识正文 |

### 5.6 维度五：推荐回复质量

| 标签 | 定义 |
|---|---|
| 可直接发送 | 准确、简洁、符合对客口径，可直接使用 |
| 轻微修改后发送 | 结论正确，仅需调整表达或补充少量信息 |
| 需要重新生成 | 存在事实、范围、语气、步骤或关键信息问题 |
| 不应生成回复 | 当前内容不适合形成推荐回复，或证据不足 |

## 6. 每条样本必须保存的字段

下面分为“必须字段”和“建议字段”。第一阶段至少保证必须字段完整。

### 6.1 身份与追溯字段

| 字段 | 要求 |
|---|---|
| 候选ID或主题ID | 必须唯一、不可重复编号 |
| 原始工单ID | 保留来源追溯，不得截断或重新编号 |
| 产品品类 | 必填 |
| 业务层级 | 自营回收、聚合回收等，必须隔离 |
| 候选生成时间 | 必填 |
| 复核人 | 必填 |
| 复核时间 | 系统自动记录，人工不可随意覆盖 |

### 6.2 模型原始结果字段

| 字段 | 要求 |
|---|---|
| 模型版本 | 必填 |
| Prompt版本 | 生成模型参与时必填 |
| 模型初标分类 | 原样保留 |
| 模型初标沉淀价值 | 原样保留 |
| 模型初标置信度 | 保存原始数值，不由人工修改 |
| 模型风险标记 | 保存重点复核、证据冲突、图片不足等信息 |
| 模型原始标题、正文、推荐回复 | 内容生成任务必须保留 |

### 6.3 人工最终结果字段

| 字段 | 要求 |
|---|---|
| 人工主题问题分类 | 必填 |
| 人工复用价值 | 有复用价值、无复用价值、暂无法判断 |
| 知识处理动作 | 四选一，必填 |
| 知识来源 | 总部标准、业务沉淀、原始案例、其他可验证来源、暂不确定 |
| 是否涉及总部标准 | 是或否 |
| 关联总部标准 | 涉及总部标准时必填 |
| 总部标准异常待反馈 | 是或否 |
| 模型判断准确性 | 正确、部分正确、错误、无法评价 |
| 正文质量 | 四级标签 |
| 推荐回复质量 | 四级标签 |
| 人工最终标题、正文、推荐回复 | 修改过或准备送审时保存 |
| 错误类型 | 使用统一选项，不只写自由备注 |
| 错误原因 | 部分正确、错误、需要重写时必填 |

### 6.4 流程与样本字段

| 字段 | 要求 |
|---|---|
| 候选价值复核结论 | 通过、修改后通过、待补充、驳回、Bad Case |
| 待发布审核结果 | 通过、修改后通过、退回、驳回、暂缓 |
| 是否为抽检样本 | 区分全量复核、随机抽检和风险抽检 |
| 样本质检状态 | 待质检、通过、退回补充、排除 |
| 数据集用途 | 未分配、训练集、验证集、长期测试集 |
| 排除原因 | 被排除时必填 |

## 7. 错误类型统一选项

建议第一版使用以下结构化错误类型，可多选：

- 沉淀价值判断错误；
- 主题问题分类错误；
- 应新增却判断为补充；
- 应补充业务知识却判断为新增；
- 错误建议修改总部标准；
- 总部标准关联错误或缺失；
- 证据不足仍给出确定结论；
- 与来源事实不一致；
- 适用范围遗漏或扩大；
- 关键条件遗漏；
- 操作步骤错误或不完整；
- 重复已有知识；
- 标题不准确；
- 正文结构或表达问题；
- 推荐回复事实错误；
- 推荐回复语气或表达问题；
- 图片或附件证据判断错误；
- 其他。

选择“其他”时必须填写错误原因。

## 8. 从零收集的操作流程

### 8.1 每条候选的人工操作顺序

```text
第一步：阅读原始问题、证据和模型初标
第二步：判断是否有复用价值
第三步：选择知识处理动作
第四步：判断是否涉及总部标准以及是否有修改权限
第五步：评价模型初标是否正确
第六步：检查并修改标题、正文和推荐回复
第七步：选择正文质量、推荐回复质量和错误类型
第八步：提交候选价值复核
第九步：通过项进入待发布审核队列
第十步：样本质检人员决定其能否成为可信人工真值
```

### 8.2 为什么“是否进入训练样本”不能由单次复核直接决定

线上已有“作为训练样本”或“是否进入再训练样本”标签，可以继续作为人工推荐，但不能直接等同于正式进入训练集。

建议含义调整为：

> “人工建议纳入训练候选池”。

正式进入训练集还必须经过系统规则和样本质检：

```text
人工勾选训练样本
        ↓
进入训练候选样本池
        ↓
检查字段完整、标签冲突、证据、权限和重复数据
        ↓
质检通过
        ↓
成为可信人工真值
        ↓
再分配到训练集、验证集或长期测试集
```

这样可以防止某一次主观修改被模型直接学走。

## 9. 样本准入和排除规则

### 9.1 可以成为可信人工真值

必须同时满足：

- 人工主题分类、复用价值和处理动作完整；
- 模型原始结果可追溯；
- 证据来源可追溯；
- 涉及总部标准时已正确关联，且没有修改总部标准；
- 人工修改前后内容可以对比；
- 需要说明原因的记录已经填写原因；
- 同一证据不存在互相冲突的最终标签；
- 测试数据、重复数据和异常数据已经排除；
- 质检人员确认可用于评估或训练。

### 9.2 只能留在待确认池

- 证据不足；
- 人工之间存在分歧；
- 与总部标准冲突；
- 需要业务负责人确认；
- 修改结果比较主观，无法写出稳定理由；
- 尚未完成必要字段。

### 9.3 必须排除训练

- 未经人工检查的自动通过记录；
- 只有模型标签，没有人工真值；
- 测试、演示或重复记录；
- 原始工单ID或来源证据无法追溯；
- 人工标签明显自相矛盾；
- 总部标准被业务侧无权限改写；
- 为了凑样本数量而复制、改写或人工制造的近重复样本；
- 已经分配到长期测试集的样本。

---

## 10. 样本分配规则

同一主题、同一工单或高度相似内容必须放在同一个数据集，不能一部分进入训练集、一部分进入测试集，否则评估结果会虚高。

建议按主题组分配：

| 数据集 | 建议比例 | 用途 |
|---|---:|---|
| 训练集 | 70% | 模型学习 |
| 验证集 | 15% | 选择模型、参数和阈值 |
| 长期测试集 | 15% | 比较新旧模型，禁止参与训练 |

如果样本总量较少，不必立即按比例切分。可以先建立收集池，达到第一轮最低样本量后再冻结数据快照并分配。

长期测试集一旦冻结，不能因为模型在其中表现不好就把答案加入训练集。需要积累下一批独立数据再训练。

## 11. 分阶段执行计划

### 阶段 0：口径确认和字段准备

目标：保证所有人对同一案例能够使用相同标签。

建议用时：1～3 个工作日。

要完成：

- 确认本方案中的三个价值标签和四个处理动作；
- 确认总部标准特殊规则；
- 确认错误类型；
- 明确复核人、分歧裁决人和样本质检人；
- 将页面已有字段与本方案字段逐项对照；
- 缺少字段时，先确定临时记录格式或等待页面补充；
- 设定正式收集开始时间和数据版本。

本阶段不训练模型。

### 阶段 1：50 条试运行样本

目标：验证标注流程是否易懂、字段是否够用。

执行方式：

- 连续收集新进入的候选，不只挑“好标”的案例；
- 50 条全部人工复核；
- 至少 20% 由第二人独立复核；
- 有分歧的案例统一裁决并记录原因；
- 检查总部标准补充是否都按“新增业务沉淀知识”处理；
- 暂不用于正式训练。

阶段验收：

- 必填字段完整率达到 95% 以上；
- 严重标签冲突已经全部裁决；
- 大部分复核人员能理解各标签差异；
- 页面或临时记录方式不会丢失模型原稿和人工终稿。

### 阶段 2：形成第一批可信样本

建议目标：累计 300～500 条经过质检的新样本。

要求：

- 所有候选继续人工复核，不启用自动通过；
- 每周检查各标签、品类和置信度区间分布；
- 防止只积累“值得沉淀”的正样本；
- 每周随机双人复核 10%；
- 高风险、总部标准冲突和新品类继续双人复核；
- 冻结第一版训练数据快照和长期测试集。

这里的 300～500 条是第一轮实验建议值，不是自动放行标准。若主要标签样本严重不平衡，应继续收集。

### 阶段 3：第一次离线训练和验证

目标：判断新模型是否比当前模型更好，不接入生产自动通过。

要完成：

- 用训练集训练候选模型；
- 使用验证集选择阈值；
- 使用长期测试集对比当前模型；
- 分别检查主题分类和沉淀价值；
- 分产品品类检查是否有明显退化；
- 输出错误案例清单；
- 对置信度进行校准，不能把模型内部 0.95 直接叫作 95% 实际正确率。

未达标时继续收集和修订口径，不上线候选模型。

### 阶段 4：影子运行

目标：新模型在线生成结果，但不改变人工流程。

执行方式：

- 新旧模型同时预测；
- 人工仍然全量复核；
- 统计每个模型版本、Prompt版本、品类、任务和置信度区间的真实准确性；
- 统计正文可直接使用率和推荐回复可直接发送率；
- 观察至少一个完整业务周期。

### 阶段 5：分级降低人工复核比例

只有影子运行稳定后，才能按区间降低候选价值人工复核比例。

建议初始规则：

| 区间真实表现 | 候选价值复核方式 |
|---|---|
| 有硬风险或样本不足 | 100% 人工复核 |
| 区间真实准确率低于 90% | 100% 人工复核 |
| 90%～95% | 50% 人工抽检 |
| 95%～97% | 20%～30% 人工抽检 |
| 97%～99% | 5%～10% 人工抽检 |
| 不低于 99%，且长期稳定、无严重错误 | 可考虑直接进入待发布审核，同时后台抽检 2%～5% |

每个“模型版本 + Prompt版本 + 品类 + 任务 + 置信度区间”建议至少有 100 条有效人工样本后，才讨论降低该区间人工比例。

任何自动通过仍然只进入待发布审核队列。

## 12. 永远不能只因高置信度自动通过的内容

以下情况属于硬风险，无论模型置信度多高，都必须人工复核：

- 来源证据不足；
- 多个来源互相冲突；
- 涉及总部标准新增、变更、冲突或权限判断；
- 图片、视频或附件是关键证据但未完整读取；
- 模型转写失败或输出不完整；
- 新产品品类、新业务流程或新规则；
- 适用范围不明确；
- 可能造成错误质检、错误报价、错误承诺或客户损失；
- 模型版本或 Prompt版本未经当前业务数据验证；
- 同一主题的人工作业结果存在分歧。

## 18. 推荐的最终执行原则

- 人工推荐训练和正式训练准入分开；

- 分类模型训练和正文生成改进分开；

## 19. 本轮 161 条测试批次的影子评测边界

本轮 161 条仅作为一次“离线/影子评测测试批次”，不改变任何生产行为。它的唯一目标是验证字段、统计口径和评测流程能否完整闭环。

本轮明确写死以下边界：

| 项目 | 本轮处理方式 |
|---|---|
| 数据身份 | `evaluation_scope = shadow_only`，`batch_type = test_batch` |
| 路由 | 不切换当前生产路由，不让候选模型接管请求 |
| 人工复核 | 按影子评测流程做全检或盲评，不因为模型置信度跳过人工真值确认 |
| 训练真值 | 不进入可信人工真值、训练集、验证集或长期测试集快照 |
| 正式训练 | 不训练、不调参、不更新阈值、不改变自动通过策略 |
| 生产发布 | 不进入正式发布审核，不生成可发布知识，不替代现有审核结果 |
| GitHub | 不提交、不推送、不创建 PR |
| 服务器 | 不更新服务器、不重建镜像、不重启容器、不改线上配置 |
| 结果用途 | 只产出字段完整性、统计可行性和流程问题清单 |

因此，161 条的结果只能回答“评测方案是否能跑通、哪些字段缺失、哪些区间样本不足”，不能回答“模型已经可以降低人工比例”。即使某个区间在 161 条中看起来达到阈值，也不得据此切换路由或执行前置复核通过。

建议在批次级别增加一个不可变的门禁字段：

```text
operational_action = no_route_change_no_training_no_release
```

只有在后续独立业务批次完成规定样本量、重复影子评测并通过门禁后，才可以另行评审是否改变复核比例。

## 20. “置信度区间—真实准确性—复核动作”字段设计

字段分成五组：批次追溯、模型输出、人工真值、复核动作和质量门禁。模型原始值必须只写入原始字段；系统计算出的区间和统计值另存，不能覆盖原始置信度。

### 20.1 批次追溯字段

| 机器字段 | 页面/报表名称 | 类型 | 规则 |
|---|---|---|---|
| `shadow_eval_id` | 影子评测ID | 字符串 | 每次评测唯一，评测重跑生成新ID |
| `test_batch_id` | 测试批次ID | 字符串 | 本轮固定指向 161 条批次 |
| `sample_id` | 样本ID | 字符串 | 一条样本一个稳定ID，不因重跑改变 |
| `case_group_id` | 主题/案例组ID | 字符串 | 同一主题或高度相似案例必须同组 |
| `evaluation_scope` | 评测范围 | 枚举 | `shadow_only` / `production`；本轮只能是 `shadow_only` |
| `source_snapshot` | 来源快照 | 字符串 | 记录输入文件或数据库快照指纹 |
| `model_version` | 模型版本 | 字符串 | 必填，不允许使用“当前版本”这类模糊值 |
| `prompt_version` | Prompt版本 | 字符串 | 生成任务必填 |
| `generated_at` | 模型生成时间 | 时间 | 系统生成 |
| `route_name` | 实际路由 | 字符串 | 只记录实际调用的路由，不因影子候选伪造生产路由 |

### 20.2 模型输出与置信度字段

| 机器字段 | 页面/报表名称 | 类型 | 规则 |
|---|---|---|---|
| `model_prediction` | 模型预测结果 | 结构化值 | 保存模型原始输出，不保存人工改写后的值 |
| `model_confidence_raw` | 模型原始置信度 | 小数 | 原样保存；建议统一到 `[0, 1]`，超界记为无效 |
| `confidence_calibrated` | 是否已校准 | 布尔 | 当前方案默认 `false`，不能把 0.95 写成 95%准确率 |
| `confidence_band` | 置信度区间 | 枚举 | 由固定边界计算，不能按结果临时改区间 |
| `model_risk_flags` | 模型风险标记 | 多选 | 证据不足、来源冲突、图片未完整读取、模型失败、新品类等 |
| `output_completeness` | 输出完整性 | 枚举 | `complete` / `partial` / `failed` |

首版建议固定以下区间，先按区间收集，不足时只允许在报表层合并相邻区间：

```text
B0: [0.00, 0.50)
B1: [0.50, 0.70)
B2: [0.70, 0.80)
B3: [0.80, 0.90)
B4: [0.90, 0.95)
B5: [0.95, 0.98)
B6: [0.98, 1.00]
```

区间边界必须在评测开始前冻结。若某区间有效样本少于最低要求，只能标记“样本不足并回到全检”，不能把它与高区间合并后宣称高准确率。

### 20.3 人工真值与可评价性字段

| 机器字段 | 页面/报表名称 | 类型 | 规则 |
|---|---|---|---|
| `truth_label` | 人工真实标签 | 结构化值 | 按本方案统一口径填写 |
| `truth_status` | 真值状态 | 枚举 | `confirmed` / `needs_adjudication` / `not_evaluable` |
| `model_correctness` | 模型判断准确性 | 枚举 | `strict_correct` / `partially_correct` / `wrong` / `not_evaluable` |
| `strict_correct` | 严格正确 | 布尔/空值 | 只有与人工真值完全一致才为 `true`；无法评价必须为空 |
| `acceptable_correct` | 业务可接受正确 | 布尔/空值 | 业务安全但不完全一致时可为 `true`，不得替代严格准确率 |
| `error_type` | 错误类型 | 多选 | 使用第 7 节统一选项 |
| `error_severity` | 错误严重度 | 枚举 | `fatal` / `major` / `minor` |
| `adjudication_status` | 分歧裁决状态 | 枚举 | `not_needed` / `pending` / `resolved` |
| `truth_reviewer` | 真值复核人 | 字符串 | 与模型生成者分开记录 |
| `truth_reviewed_at` | 真值复核时间 | 时间 | 系统记录 |
| `evidence_reference` | 证据引用 | 字符串/数组 | 能回到原始工单、图片、附件或标准条款 |

统计时必须区分以下三个数量：

```text
n_scored       = 有模型输出且进入该区间的样本数
n_valid_truth  = truth_status = confirmed 的样本数
n_not_evaluable = 无法形成稳定人工真值的样本数
```

`not_evaluable` 不能计为正确，也不能悄悄从分母删除后不报告；它应单独形成“不可评价率”。

### 20.4 复核动作与前置复核通过字段

| 机器字段 | 页面/报表名称 | 类型 | 规则 |
|---|---|---|---|
| `review_mode_actual` | 实际复核方式 | 枚举 | `full_review` / `risk_sample` / `random_sample` / `pre_review_pass_candidate` |
| `review_required_level` | 规则要求复核级别 | 枚举 | 根据门禁计算，不由人工随意降低 |
| `risk_sample_selected` | 是否命中风险抽检 | 布尔 | 命中硬风险时必须为 `true` |
| `random_sample_selected` | 是否命中随机抽检 | 布尔 | 使用可复现随机种子 |
| `review_outcome` | 复核结果 | 枚举 | `passed` / `corrected` / `rejected` / `pending` |
| `pre_review_pass_status` | 前置复核通过状态 | 枚举 | `not_eligible` / `candidate` / `approved` / `revoked` |
| `pre_review_pass_reason` | 前置复核通过依据 | 结构化文本 | 必须引用区间、样本量、准确率下界、严重错误率和覆盖率 |
| `fallback_to_full_review` | 是否回退全检 | 布尔 | 任一门禁失败即为 `true` |

“前置复核通过”只表示候选价值复核可以在规则允许时跳过人工步骤，后续仍进入“待发布审核”；它不等于发布通过、训练准入或人工真值。

## 21. 统计口径和门禁公式

### 21.1 区间真实准确性

对每个“模型版本 + Prompt版本 + 产品品类 + 任务 + 置信度区间”分层统计。主指标使用严格准确率：

```text
strict_accuracy = strict_correct_true / n_valid_truth
```

同时报告：

```text
coverage              = n_valid_truth / n_scored
not_evaluable_rate    = n_not_evaluable / n_scored
acceptable_accuracy   = acceptable_correct_true / n_valid_truth
fatal_error_rate      = fatal_error_count / n_valid_truth
major_error_rate      = major_error_count / n_valid_truth
```

`strict_accuracy` 是判断是否可以降低人工复核比例的主指标；`acceptable_accuracy` 只能用于观察“业务可接受但需要措辞或边界修订”的情况，不能替代严格准确率。

### 21.2 置信区间和样本不足

报表除了点估计，必须显示 95% 二项比例 Wilson 下限 `accuracy_ci95_lower`。门禁使用下限，不使用单纯的样本点估计。这样可以避免 10 条样本中 10 条正确就被误判为“稳定 100%”。

每个分层组合至少需要 100 条 `n_valid_truth` 才能讨论降低人工比例；若评估的是最高风险的“前置复核通过”，建议至少 200 条有效真值，并且来自两个连续、相互独立的业务窗口。低于要求时：

```text
样本不足 -> 统计可以展示 -> 运营动作必须回到 full_review
```

不得用 `n_scored` 冒充 `n_valid_truth`，不得用 `not_evaluable` 样本补足最低样本量。

### 21.3 复核动作门禁

以下是“设计门槛”，不是本轮 161 条的放行结果：

| 门禁结果 | 必要条件 | 允许的复核动作 |
|---|---|---|
| `FULL_REVIEW` | 有硬风险；或 `n_valid_truth` 不足；或严格准确率 95%下限低于 90%；或 `fatal_error_rate > 0`；或覆盖率低于 95% | 100%人工复核 |
| `RISK_SAMPLE` | `n_valid_truth >= 100`、严格准确率点估计不低于 95%、95%下限不低于 90%、无致命错误、覆盖率不低于 95%，且风险样本仍全检 | 硬风险全检 + 其余建议 20%～30%抽检 |
| `RANDOM_SAMPLE` | `n_valid_truth >= 100`、严格准确率点估计不低于 97%、95%下限不低于 95%、无致命错误、连续两个窗口稳定 | 建议 5%～10%随机抽检，并保留风险全检 |
| `PRE_REVIEW_PASS_CANDIDATE` | `n_valid_truth >= 200`、连续两个窗口稳定、严格准确率点估计不低于 99%、95%下限不低于 97%、无致命错误、覆盖率不低于 98%、无总部标准/证据冲突硬风险 | 可提交前置复核通过评审；后台仍抽检 2%～5% |

只要任一条件失效，就设置 `fallback_to_full_review = true`。自动回退不需要人工选择，也不能由旧的“已通过”状态覆盖。

## 22. 161 条批次的影子评测流程

本轮按下面顺序执行，所有中间产物只留在本地评测目录或本地数据库中：

```text
冻结 161 条输入快照和指纹
        ↓
记录当前实际路由、模型版本、Prompt版本
        ↓
对同一输入保存模型原始输出和原始置信度
        ↓
人工先独立形成 truth_label（尽量不先看模型置信度）
        ↓
第二人对抽样/风险样本复核，分歧进入裁决
        ↓
把人工真值与模型输出按 sample_id 对齐
        ↓
按版本、品类、任务、置信度区间分层统计
        ↓
生成准确率点估计、Wilson下限、覆盖率、不可评价率和严重错误清单
        ↓
只输出 shadow_eval_report，不生成路由或训练配置
```

为了防止评测污染，建议执行以下控制：

1. 真值复核阶段不把模型置信度作为人工提示；如必须展示模型结果，先锁定人工标签再展示模型结果。
2. 抽检使用固定随机种子并保存种子、抽样规则和抽样清单，使同一批次可复现。
3. 主题或高度相似案例按 `case_group_id` 进行分组，不能把同一案例拆到“已看”和“未看”两边。
4. 对 `not_evaluable`、`needs_adjudication` 和缺失证据样本单独列清单，不得静默丢弃。
5. 统计完成后导出“原始明细 + 聚合统计 + 错误案例 + 门禁判定”四类结果，任何人可从聚合结果回钻到样本。

建议的本地结果结构如下，名称只是评测产物约定，不代表需要立即开发线上接口：

```text
shadow_eval/
  <shadow_eval_id>/
    input_snapshot.json
    sample_annotations.jsonl
    aggregate_by_confidence_band.csv
    aggregate_by_strata.csv
    fatal_and_major_errors.csv
    shadow_eval_report.md
    gate_decision.json
```

## 23. 影子评测报告的最低输出

每次影子评测至少应输出以下表格，且报告首页必须写明“本结果不改变路由、不进入正式训练真值”：

| 报表 | 必含字段 |
|---|---|
| 批次概览 | 评测ID、批次ID、样本总数、有效真值数、不可评价数、模型/Prompt版本、`operational_action` |
| 区间统计 | 置信度区间、`n_scored`、`n_valid_truth`、严格正确数、严格准确率、95%下限、覆盖率、严重错误率 |
| 分层统计 | 产品品类、任务、模型版本、Prompt版本、置信度区间及以上全部指标 |
| 复核模拟 | 若按门禁计算将是全检/风险抽检/随机抽检/前置复核候选中的哪一种，以及触发和未满足的条件 |
| 错误清单 | sample_id、区间、模型输出、人工真值、错误类型、严重度、证据引用、是否硬风险 |
| 数据质量 | 缺失字段、重复样本、分组泄漏、分歧未裁决、不可评价原因 |

报告中的“复核模拟”只是规则计算结果，必须标注 `simulated_only = true`。本轮 161 条即使模拟结果显示某区间可抽检，也只作为方案验证，不执行抽检放行。

## 24. 本轮 161 条的继续/停止标准

### 可以继续完善评测流程的情况

- 161 条全部能关联到唯一 `sample_id` 和来源快照；
- 模型版本、Prompt版本和原始置信度完整；
- 人工真值、不可评价和分歧状态可以区分；
- 区间统计能从明细重新计算；
- 任何一条“前置复核通过模拟结果”都明确标注为未生效；
- 不需要修改生产路由即可完成双跑和报表生成。

### 必须停止并先修正评测数据的问题

- 161 条中存在无法确认来源或批次边界的样本；
- 原始置信度被人工覆盖，无法恢复；
- 模型输出与人工真值无法按稳定ID对齐；
- `not_evaluable` 被当成正确或被静默删除；
- 同一主题被拆到不同数据集或不同复核状态；
- 评测脚本会写入生产路由、训练配置、正式审核队列或服务器；
- 结果报告无法复算，或只能依赖人工手工修改统计数字。

本轮结束时的合格交付物是“可复算的影子评测报告和字段问题清单”，不是“自动通过开关”“新模型”“训练数据集”或“线上发布结果”。
