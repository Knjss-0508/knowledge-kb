# 模型学习、置信度分级复核与知识沉淀标注方案（讨论稿）

> 状态：讨论中，**尚未按本文修改代码或启用自动放行**  
> 日期：2026 年 9 月 13 日  
> 适用范围：Answer Hub 的主题分类、沉淀价值判断、知识转写、推荐回复和人工复核流程

## 先看结论

我们要做的不是“模型置信度高就直接通过”，而是让系统形成下面的闭环：

```text
模型初标
  ↓
按置信度区间归类
  ↓
查看该区间经过人工复核后的真实准确性
  ↓
决定本条是：全量人工复核 / 按比例抽标 / 业务直接通过并后台抽检
  ↓
人工确认或修改
  ↓
把人工真值、修改原因和终稿沉淀为训练与改进数据
  ↓
周期性训练、验证和灰度启用新模型
```

同时，必须把三个容易混淆的判断拆开：

| 要回答的问题 | 正确的判断结果 | 不能混为一谈 |
|---|---|---|
| 这个主题有没有复用价值？ | 有复用价值 / 无复用价值 / 暂无法判断 | 主题是否有价值，不等于当前草稿写得好 |
| 当前应如何处理？ | 新增知识 / 补充已有知识 / 待补充证据 / 不沉淀 | “已有知识已覆盖”不等于“不值得” |
| 当前正文和推荐回复能否使用？ | 可直接使用 / 轻微修改 / 需要重写 / 无法形成知识 | 有价值的主题也可能需要重写 |

这份文档的核心原则是：**先用人工真值证明模型在某个场景真的可靠，再逐步减少人工工作量；不让模型用自己的结果证明自己正确。**

---

## 1. 要解决什么问题

当前流程已有模型初标、置信度、人工复核、人工反馈和本地实验训练能力，但仍有三个现实问题：

1. 模型初标准确性不稳定，不能只看模型自己报出的置信度。
2. 模型转写出的知识正文、标题和推荐回复，经常需要人工修改。
3. 人工已经在纠错，但这些纠错结果尚未完整变成下一轮模型可学习、可验证的数据闭环。

目标不是马上取消人工，而是按模型在不同场景中的**已验证真实表现**，逐步把人工从“逐条重复审核”转为“抽检、处理例外和维护标注口径”。

---

## 2. 一句话原则

> **置信度负责分组，人工历史准确性负责决定复核比例，硬风险始终优先于自动通过。**

例如，一条初标置信度为 93% 的内容，不应仅因它大于 90% 就通过，而应先判断：

```text
它属于 90%～95% 的置信度区间；
该区间、该产品品类、该模型版本、该 Prompt 版本的人工验证准确性是多少；
样本量是否足够；
本条是否存在来源不足、标准冲突等硬风险。
```

只有上述条件都满足，系统才可以降低人工复核比例。

---

## 3. 需要分清的四个概念

### 3.1 模型置信度

模型对自己某个判断的把握程度，例如“这条内容值得沉淀”的模型置信度为 0.93。

**它不是实际正确率。** 未经人工校准的 0.93，不能解释为“93% 概率正确”。

### 3.2 区间真实准确性

同一置信度区间的模型判断，经过人工复核后实际正确的比例。

例如：

```text
90%～95% 区间：人工验证 500 条，其中 478 条正确
区间真实准确性 = 478 / 500 = 95.6%
```

这才是决定是否可以抽标、是否可以减少人工复核的主要依据。

### 3.3 自动放行精确率

模型判定“可以通过”的内容中，最终被人工确认“确实可以通过”的比例。

它与整体准确率不同。对于知识库而言，错误知识被放行的代价较高，因此“是否允许直接通过”尤其要看这个指标。

### 3.4 硬风险

硬风险出现时，无论置信度多高、历史准确率多好，都必须人工复核。包括：

- 模型调用失败、超时或使用了降级结果；
- 来源证据不足、来源相互冲突；
- 回收业务层级或产品品类冲突；
- 标准引用无法追溯、标准映射不一致；
- 图片模糊、图片不足或模型仅凭图片做确定结论；
- 主题分类为“不确定”；
- 内容包含来源中不存在的阈值、规则、对象、结论；
- 新模型、新 Prompt、新品类尚无有效验证样本；
- 置信度为空、异常或无法解析。

## 4. 建议的总流程

```text
【来源会话、图片、人工原始判定】
                ↓
        主题拆分与聚类
                ↓
 ┌───────────────────────────┐
 │ ① 沉淀价值与处理动作判断  │
 │   是否有复用价值？         │
 │   新增 / 补充 / 待证据 / 不沉淀 │
 └───────────────────────────┘
                ↓
      仅对可处理主题生成草稿
                ↓
 ┌───────────────────────────┐
 │ ② 知识转写                │
 │   标题、正文、推荐回复     │
 └───────────────────────────┘
                ↓
 ┌───────────────────────────┐
 │ ③ 内容质量判断            │
 │   事实、范围、边界、回复   │
 └───────────────────────────┘
                ↓
      先检查是否存在硬风险
         ├─ 有 → 全量人工复核
         └─ 无 → 按置信度区间和历史准确性路由
                    ├─ 全量人工复核
                    ├─ 高比例抽标
                    ├─ 低比例抽标
                    └─ 业务直接通过 + 后台抽检
                ↓
       人工确认 / 修改 / 驳回
                ↓
      保存原稿、终稿、错误类型、人工结论
                ↓
   训练候选模型、验证、灰度、可回滚上线
```

### 重要约束

1. “是否值得沉淀”必须在生成正文之前判断。
2. 内容质量审核不能为了补救正文不好，擅自改判沉淀价值。
3. 自动放行只代表跳过当前层级的人工复核；是否直接进入正式知识库，还要由后续 CZ 终审和发布门禁决定。
4. 未经人工确认的自动通过结果，**不能**当作“人工真值”直接用于训练。

## 5. 置信度分级与人工复核策略

### 5.1 先按置信度分组

建议初期使用五档。后续数据量足够时，可拆成每 5% 一档。

| 模型置信度区间 | 含义 |
|---|---|
| 95%～100% | 极高置信 |
| 90%～95% | 高置信 |
| 80%～90% | 中等置信 |
| 70%～80% | 低置信 |
| 0%～70% | 极低置信 |

> 置信度区间只用于统计与分组；它本身不直接决定能否放行。

### 5.2 再按区间真实表现决定人工策略

下面是建议的初始规则，具体数值应配置化，并在积累真实数据后调整。

| 前提条件 | 人工处理策略 | 建议抽标比例 |
|---|---|---:|
| 存在硬风险 | 全量人工复核 | 100% |
| 有效人工样本不足 100 条 | 全量人工复核 | 100% |
| 区间真实准确性 < 90% | 全量人工复核 | 100% |
| 90% ≤ 准确性 < 95% | 高比例抽标 | 50% |
| 95% ≤ 准确性 < 98% | 中比例抽标 | 20%～30% |
| 98% ≤ 准确性 < 99% | 低比例抽标 | 5%～10% |
| 准确性 ≥ 99%，且连续稳定 | 业务直接通过 + 后台质量抽检 | 2%～5% |

### 5.3 “95%准确性”应该怎么理解

如果某个区间真实准确性达到 95%，可以开始减少人工，但不建议直接停止人工抽检。

```text
95% 准确性
→ 适合改为 20%～30% 人工抽标
→ 不适合直接取消人工质量监控
```

如果“模型通过”之后还存在 CZ 终审、入库审核或发布审核，95% 可以作为灰度降低前置人工复核比例的起点；如果模型通过后会直接正式入库，则应要求更高的自动放行精确率，例如 98%～99% 以上。

### 5.4 抽标不应只有随机抽取

每一批抽标建议由两部分构成：

| 抽标类型 | 目的 |
|---|---|
| 随机抽标 | 真实反映该置信度区间的整体准确性 |
| 风险优先抽标 | 尽早发现新机型、新表达、图片、边界和标准问题 |

风险优先对象包括新品类、新模型版本、新 Prompt、首次出现的机型、模型多个标签分数接近、近期错误率上升、图片依赖强、标准引用复杂等内容。

## 6. “值得沉淀”不应只剩是或否

目前最容易混乱的地方是：把“没有价值”“有价值但证据不足”“有价值但已有知识覆盖”都写成“不值得沉淀”。这会使人工口径不一致，也会让训练模型学错。

建议将判断拆成两层。

### 6.1 第一层：是否具有复用价值

| 结果 | 含义 |
|---|---|
| 有复用价值 | 能帮助未来处理相同或相似问题 |
| 无复用价值 | 仅能说明当前工单，不能迁移到其他场景 |
| 暂无法判断 | 有潜在价值，但当前信息不足或存在冲突 |

### 6.2 第二层：系统处理动作

| 处理动作 | 适用情况 | 是否生成正式知识草稿 |
|---|---|---|
| 新增知识 | 有复用价值，证据充分，现有知识未覆盖 | 是 |
| 补充已有知识 | 有复用价值，但只是已有知识的新边界、例外、步骤或纠正 | 是，作为补充候选 |
| 待补充证据 | 有潜在价值，但对象、标准、图片、边界或步骤不充分 | 否，保留待补充记录 |
| 不沉淀 | 纯个案、无通用规则、无业务价值或无法形成知识 | 否 |

### 6.3 判断“有复用价值”的最小条件

一条主题要进入“新增知识”或“补充已有知识”，建议至少同时满足：

1. **对象明确**：清楚知道适用于哪个业务层级、产品品类、机型/代际、部位或功能。
2. **触发场景明确**：知道什么时候应该使用这条知识。
3. **可执行内容明确**：至少有判定口径、检查步骤、查询方法、边界、例外或区分方法之一。
4. **证据可追溯**：关键结论可回到有效标准、人工确认结论、完整会话、可信产品事实或足够的案例证据。
5. **适用边界明确**：说明适用范围，必要时说明不适用条件。

### 6.4 正反例

| 例子 | 正确判断 | 原因 |
|---|---|---|
| “AirPods 一代不要求检查‘查找’功能。” | 新增或补充已有知识 | 有明确对象和可复用的机型边界 |
| “这台 AirPods 已解绑，可以回收。” | 不沉淀 | 只是当前设备结论，无法外推 |
| “某机型电池健康度无法读取时，先核对设备信息，再与检测工具交叉确认。” | 新增或补充已有知识 | 有明确场景和可执行步骤 |
| “图片不清楚，需要补充近景后才能判断。” | 待补充证据 | 有处理价值，但当前不能形成具体判定知识 |
| “已有知识已完整覆盖同一对象、条件、结论和边界。” | 补充已有知识或不新增 | 不是没有价值，而是不应重复建知识 |
| “这次看图属于正常。” | 不沉淀 | 没有可迁移的判断条件或边界 |

## 7. 正文和推荐回复：它们是另一套质量问题

### 7.1 必须分开判断

```text
主题值得沉淀
≠ 当前知识正文合格
≠ 推荐回复可以直接发送
```

一个主题可以很有价值，但模型写出的草稿仍可能存在事实错误、适用范围缺失、模板化表达、遗漏边界或回复不自然等问题。

### 7.2 知识正文质量等级

| 等级 | 定义 | 建议动作 |
|---|---|---|
| 可直接使用 | 事实、范围、结构和边界都正确，基本无需改动 | 可抽标或通过 |
| 轻微修改 | 只需调整措辞、格式、标题或少量表达 | 人工快速修改，作为优质样本 |
| 需要重写 | 核心规则、范围、结构或关键步骤有问题 | 模型二次重写后复核，或人工重点修改 |
| 无法形成知识 | 证据不足、主题混杂或无法形成可复用表达 | 不进入正式知识 |

### 7.3 合格正文至少应包含什么

通常至少覆盖下列四项中的三项；涉及高风险判定时，建议四项齐全：

1. **适用对象**：什么品类、机型、部位或功能。
2. **触发场景**：什么情况下使用这条知识。
3. **规则或步骤**：如何判断、如何检查、如何查询或如何处理。
4. **边界与例外**：什么情况下不能直接适用，何时需要补充证据。

示例：

```text
适用对象：某指定机型。
触发场景：检测工具无法读取电池健康度。
处理步骤：
1. 在“设置—通用—关于本机”核对设备信息。
2. 再与检测工具结果交叉确认。
边界：该步骤只能用于信息核对，不能替代需要实物检测的功能判断。
```

### 7.4 推荐回复的合格标准

推荐回复的目标是“人工可以直接发送，或仅需轻微调整后发送”，不是把知识正文复制一遍。

一条合格推荐回复应当：

- 只回答当前一个主题，不能混入同一工单的其他问题；
- 保留关键对象、机型和适用范围；
- 直接给出结论或下一步动作；
- 证据不足时明确说明需要补什么，而不作确定承诺；
- 不出现模型、复核、置信度、证据包、候选知识等内部术语；
- 语气自然、简洁，不用无意义的客套和模板话。

不推荐：

```text
您好，关于您咨询的问题，需要结合相关标准和实际情况综合判断。
```

更合适：

```text
该机型无法直接读取电池健康度时，先在“设置—通用—关于本机”核对设备信息，再结合检测工具结果确认；两边结果不一致时，暂时不要只按工具结果下结论。
```

> 当前项目中推荐回复的字数要求可保留为软约束；是否“可直接发送”应比是否达到固定字数更重要。

## 8. 模型能做什么，不能做什么

| 任务 | 是否适合模型完成 | 当前适合的模型角色 | 人工仍需负责什么 |
|---|---|---|---|
| 判断主题分类 | 适合 | 本地分类模型或大模型 | 处理边界不清、冲突和新品类 |
| 判断是否有复用价值 | 适合，但须人工真值训练 | 本地分类模型或大模型 | 校准口径、处理疑难案例 |
| 判断新增/补充/待证据/不沉淀 | 适合辅助判断 | 大模型 + 规则 + 已有知识匹配 | 确认知识库治理决策 |
| 生成标题、正文、推荐回复 | 适合生成初稿 | MiMo 等生成模型 | 处理事实错误、重大重写 |
| 审核正文事实和边界 | 适合辅助审核 | 独立质量审核模型 + 确定性规则 | 裁决硬风险和复杂业务判断 |
| 模型自行证明“自己正确” | 不适合 | 不应允许 | 必须以人工抽检和独立验证为准 |

### 关键设计：三个角色不要混成一个

| 角色 | 职责 |
|---|---|
| 价值判定模型 | 判断复用价值和处理动作 |
| 知识转写模型 | 生成标题、正文和推荐回复初稿 |
| 内容质量模型 | 检查事实、范围、边界、结构和回复可用性 |

底层可以暂时仍使用同一个大模型服务，但三类调用的输入、输出、置信度、准确率和验收标准必须分别统计。尤其不能让“生成草稿的同一次输出”直接给自己打高分后自动放行。

## 9. 人工修改要如何变成模型可学习的数据

人工不应只写一个“已修改”或自由备注。每次复核建议至少保存下面的信息：

| 字段 | 作用 |
|---|---|
| 模型版本、Prompt 版本 | 区分不同模型和提示词的表现 |
| 产品品类、业务层级 | 防止把一个品类的准确性套用到另一个品类 |
| 原始模型判断、原始置信度 | 用于计算区间准确性 |
| 人工最终判断 | 形成真值 |
| 模型原始标题/正文/回复 | 保留改前内容 |
| 人工最终标题/正文/回复 | 形成可学习终稿 |
| 修改类型 | 便于统计模型具体错在哪里 |
| 修改原因 | 记录业务口径与特殊背景 |
| 是否进入训练集 | 只让确认可信的数据进入训练 |
| 是否属于随机抽标或风险抽标 | 防止统计口径失真 |

### 建议的结构化修改类型

| 类型 | 含义 |
|---|---|
| 事实错误 | 与来源事实或人工确认结论不一致 |
| 无来源扩写 | 模型补充了输入中不存在的事实、阈值或标准 |
| 适用范围错误 | 把单机型、单代际或局部场景扩大了 |
| 结论过度 | 证据不足却给出确定结论 |
| 缺少边界 | 没有说明不适用或需补证据的情况 |
| 缺少关键步骤 | 正文无法执行或不能解决问题 |
| 主题混杂 | 把其他原子问题混入当前知识 |
| 标题不准确 | 标题太宽、太窄、不自然或不便检索 |
| 推荐回复不自然 | 像内部报告、模板化或不适合直接发送 |
| 推荐回复不完整 | 没有回答问题或没有给下一步动作 |
| 标准引用错误 | 标准不存在、映射错误或不可追溯 |
| 图片判断错误 | 图片证据不足却给出结论 |
| 重复已有知识 | 没有新增边界、例外或操作差异 |

> 未被人工抽检的自动通过记录可以保留用于运营追踪，但不能标为“人工确认正确”，不能直接作为高质量训练真值。

---

## 10. 生成质量如何真正变好

目前的本地实验模型主要适合学习“主题分类”和“沉淀价值”，不适合直接生成自然语言正文或推荐回复。正文和回复仍需要生成模型完成。

即使暂时不对生成模型做参数微调，也可以先采用以下安全、可回滚的改进路径：

### 10.1 优质示例检索

生成一条新草稿前，按产品品类、问题类型、对象、现象和内容类型，检索少量人工确认过的优质样例。

模型学习的是：

- 正确的结构；
- 如何保留机型和范围；
- 如何表达边界；
- 推荐回复的自然语气。

模型不能复制示例中与当前主题无关的事实。

### 10.2 先审核，再限定范围重写

建议后续增加独立的“自动修订”环节：

```text
第一次生成草稿
→ 质量检查指出具体问题
→ 只按问题清单重写
→ 再做确定性检查
→ 仍不合格才转人工重点复核
```

例如质量检查结果为：

```text
1. 推荐回复混入了另一个主题；
2. 正文遗漏适用机型；
3. “一定可以回收”没有来源支持。
```

重写任务必须限制为：**只修复上述问题，不增加新事实。**

### 10.3 再考虑微调

只有积累足够多、质量稳定的配对数据后，才评估生成模型微调：

```text
来源证据 + 模型原稿 + 人工修改原因 + 人工终稿
```

现阶段不应假设当前 MiMo 服务已支持或已接通微调。先做好优质样例检索、结构化反馈和自动二次修订，通常更容易验证效果，也更容易回滚。

## 11. 统计口径与模型验收

所有统计至少按以下维度拆分：

```text
模型版本
+ Prompt 版本
+ 任务类型（价值判断 / 正文质量 / 推荐回复质量）
+ 回收业务层级
+ 产品品类
+ 置信度区间
```

不能只看项目总体准确率。例如：

```text
手机品类，90%～95% 区间：准确率 98%
平板品类，90%～95% 区间：准确率 91%
```

此时手机可以降低人工比例，平板仍应保持高比例或全量人工复核；不能因手机表现好而一起放行。

### 最少应持续观察的指标

| 指标 | 要回答的问题 |
|---|---|
| 主题分类准确率 | 分类是否正确 |
| 沉淀价值/处理动作准确率 | 是否正确区分新增、补充、待证据和不沉淀 |
| 自动放行精确率 | 模型说“可以通过”的内容中，有多少人工也同意通过 |
| 正文可直接使用率 | 人工无需修改的比例 |
| 推荐回复可直接发送率 | 人工无需修改的比例 |
| 重大错误率 | 事实、范围、标准、结论等重大问题的比例 |
| 人工修改率与修改类型分布 | 模型最常在哪些环节出错 |
| 按品类/区间的样本量 | 当前结论是否可靠 |

### 新模型不能自动替换旧模型

推荐采用受控升级：

```text
积累人工真值
→ 固定训练数据快照
→ 训练候选模型
→ 使用独立验证集评估
→ 与当前生产模型比较
→ 分品类检查是否退化
→ 人工确认后小范围灰度
→ 保留旧版本，可一键回滚
```

新模型至少应满足：

- 验证样本量足够；
- 自动放行精确率不下降；
- 重点品类与重点错误类型不退化；
- 置信度区间已经重新校准；
- 模型版本、训练数据指纹、训练时间和评估报告可追溯；
- 灰度期间可通过总开关立即回到人工复核。

## 12. 建议的实施顺序

### 阶段 0：先统一人工标注口径

目标：让不同人工审核者对相同案例得到一致结论。

要完成的事：

1. 确认“新增知识 / 补充已有知识 / 待补充证据 / 不沉淀”四种处理动作。
2. 确认正文质量和推荐回复质量四级标准。
3. 确认结构化错误类型。
4. 每种标签收集 10～20 个真实正反例，作为人工标注手册和模型示例。

### 阶段 1：影子运行与数据记录

目标：不改变现有审核动作，先知道模型实际准确性。

要完成的事：

1. 记录每个任务的模型结果、置信度、模型版本、Prompt 版本。
2. 记录人工最终结果、修改类型和终稿。
3. 按置信度区间、品类和任务类型生成准确性报表。
4. 保持所有候选人工复核，不启用自动放行。

### 阶段 2：置信度分级抽标

目标：只在有足够证据的区间减少人工量。

要完成的事：

1. 配置各区间的最低样本量、准确率门槛和抽标比例。
2. 抽标同时包含随机样本和风险优先样本。
3. 硬风险内容始终全量人工复核。
4. 抽检准确性下降时，自动提高人工复核比例或回退到全量复核。

### 阶段 3：改善正文和推荐回复

目标：降低“模型草稿需要人工大改”的比例。

要完成的事：

1. 建立人工确认的优质示例库。
2. 生成前检索相似优质示例。
3. 对可修复问题启用“质量检查 → 限定范围重写”。
4. 单独统计正文可直接使用率和推荐回复可直接发送率。

### 阶段 4：周期性训练与灰度升级

目标：让模型从可靠的人类反馈中逐步提高分类与路由能力。

要完成的事：

1. 周期性冻结人工确认训练集。
2. 训练候选分类模型并生成评估报告。
3. 与当前模型比较，确认没有关键品类退化。
4. 经人工确认后，按品类灰度启用。

## 13. 当前项目基础与待开发边界

### 已有基础

当前项目已经具备部分可复用能力：

- 模型初标和相应置信度字段；
- 主题分类和沉淀价值的本地实验训练模型；
- 人工复核、反馈事件、是否进入训练集/再训练样本字段；
- 自动审核策略、最低置信度、最少验证样本、准确率和自动放行精确率门槛；
- 按品类灰度和紧急停止开关。

### 本方案后续需要补齐的能力

- 将“新增 / 补充 / 待证据 / 不沉淀”作为明确的业务处理动作；
- 对每项任务按置信度区间统计真实准确性；
- 根据统计结果动态路由全量复核、抽标或直接通过；
- 把人工终稿与结构化修改原因稳定写入训练和示例数据；
- 建立优质示例检索和自动二次修订；
- 建立候选模型训练、验证、灰度和回滚流程；
- 将“模型置信度”校准为可解释的实际可靠性，而不是只保留模型内部评分。

## 14. 需要业务确认的事项

以下问题会影响后续代码设计，建议在开发前确认：

1. **“直接通过”的业务含义**：是跳过当前初标人工复核，但仍进入 CZ 终审；还是允许直接入正式知识库？
2. **四种处理动作是否确认**：新增知识、补充已有知识、待补充证据、不沉淀。
3. **“已有知识已覆盖”的默认动作**：仅匹配引用已有知识，还是允许人工选择补充已有知识？
4. **哪些错误视为重大错误**：例如事实错误、标准引用错误、适用范围扩大，是否一律视为重大错误？
5. **正文与推荐回复的人工验收标准**：是否采用“可直接使用 / 轻微修改 / 需要重写 / 无法形成知识”四级？
6. **初始样本量与门槛**：是否以每个“模型版本 + Prompt + 品类 + 任务 + 置信度区间”至少 100 条人工样本作为开始降低人工比例的保守门槛？
7. **抽标比例**：是否先采用本文的 50% / 20%～30% / 5%～10% / 2%～5% 建议值？
8. **人工终稿使用范围**：哪些人工确认稿可进入优质示例库与训练集，是否需要二次审批？

---

## 15. 建议的下一步

在改代码前，建议先用真实业务案例完成一份“小型标注口径表”：

1. 选择 20～40 条具有代表性的历史主题；
2. 对每条分别人工标注：复用价值、处理动作、正文质量、推荐回复质量、错误类型；
3. 对有分歧的案例写明最终口径；
4. 用这份人工一致的样本，作为后续测试集、提示词示例和训练集筛选依据。

这样开发出来的不是“模型替人随便打标签”，而是把已经确认的业务判断标准固化到系统中，并持续用人工抽检验证它是否仍然可靠。
