# MiMo API 性能与容量调研（官方资料）

调研日期：2026-08-11
范围：仅引用小米 MiMo 官方文档；不包含 API Key、真实会话或运行数据。

## 结论

当前短文本、结构化的原子问题提取与主题聚类，应优先显式关闭深度思考，并为每个
请求设置足够但紧凑的 `max_completion_tokens`。MiMo 的该参数同时限制推理和可见输出；
不设置时，模型默认允许较大的生成上限，容易拉长响应时间。

官方没有公布每个账号的具体并发数、服务端延迟 SLA 或容量扩容接口。因此不能从
`100 RPM` 推导出安全的并发值，仍需使用脱敏小样本做实测。服务端高负载可能导致响应
延迟、`429` 或 `503`；应使用有限次数、带抖动的指数退避，并在连续失败后转人工审核。

## 官方能力与限制

| 项目 | 官方说明 | 对本项目的影响 |
| --- | --- | --- |
| 生成长度 | `max_completion_tokens` 限制补全 token 总数，包含可见输出和推理 token。`mimo-v2.5` 默认 32768，`mimo-v2.5-pro` 默认 131072，允许范围 1～131072。 | 对小型 JSON 结果显式设置合理上限，避免为不需要的长推理保留大输出预算。 |
| 深度思考 | `mimo-v2.5` 和 `mimo-v2.5-pro` 默认开启深度思考；官方明确说明开启会增加响应延迟。可通过 `thinking: {"type": "disabled"}` 关闭。 | 原子提取、聚类均应确认请求显式关闭深度思考；这是最直接的延迟优化项。 |
| 流式输出 | Chat Completions 支持流式输出。结构化 JSON 的流式内容须在客户端拼接完整后再解析。 | 流式不能保证缩短总耗时，但能显示模型正在返回，改善“看似卡住”的体验。严格 JSON 仍须完成拼接与校验。 |
| 限流和容量 | 每账号有模型并发上限；高负载可能导致响应延迟或 `429`。`mimo-v2.5`、`mimo-v2.5-pro` 的公开限额均为 100 RPM、10M TPM；具体并发值未公开。 | 以 20 条脱敏样本逐级测试并发和批量，不能只依据 RPM 设定生产并发。 |
| 故障处理 | 对 `429`，官方建议指数退避、重试或降低频率；对 `503`，官方说明为服务器负载过高，建议稍后重试。 | 将超时、429、500、503 作为可恢复的短暂错误，采用有限重试；达到阈值后熔断并人工审核，不得无限重试。 |

## 建议的压测前请求形态

以下是基于官方文档的请求层建议，不代表已验证的生产参数：

```json
{
  "stream": true,
  "max_completion_tokens": 1024,
  "thinking": {"type": "disabled"}
}
```

`max_completion_tokens` 应按实际 JSON 长度预留余量；设置过小会使结构化输出截断，导致
JSON 无法解析。若实际输出超过 1024，应基于压测结果提高该值，而不是直接恢复默认上限。

## 后续 20 条压测判定

1. 使用已脱敏、固定的 20 条小样本，不拉取第二部分新数据，也不写入正式队列。
2. 先验证上述请求形态在 1 并发下的成功率和 p95 耗时，再逐级提高并发和批次；每档只改变一个变量。
3. 记录每档的总耗时、单请求耗时、超时/429/5xx 数量、输出截断数和人工审核降级数。
4. 仅在零输出截断、无熔断且失败率满足项目验收要求时，才选择更高吞吐档位；否则保持人工优先审核并联系 MiMo 官方支持。

## 2026-08-11 固定 20 条压测结果

压测只使用既有的 131 条工作簿中的前 20 条，参数为关闭深度思考、
`max_completion_tokens=2048`、不附媒体；不拉取第二部分数据，也不运行知识转写。

| 并发 | 原子提取批次 | 聚类批次 | 用时 | 结果 |
| --- | --- | --- | --- | --- |
| 2 | 4 条 / 16000 字符 | 6 个原子问题 | 414 秒 | 1 个原子提取结果进入人工审核 |
| 4 | 4 条 / 16000 字符 | 6 个原子问题 | 214 秒 | 0 个模型调用失败，0 个原子/聚类失败，未熔断 |
| 6 | 4 条 / 16000 字符 | 6 个原子问题 | 256 秒 | 1 次聚类 JSON 重复分配；已拆批恢复，未熔断 |

因此生产默认固定为 4 并发。该结果说明本地 CPU 不是瓶颈；更高并发会增加 MiMo
服务端生成结构化输出异常的概率，且没有提高吞吐。若后续出现 429、503 或响应总超时，
先临时降到 2 并发并保留熔断与人工审核，不应继续提高并发。
