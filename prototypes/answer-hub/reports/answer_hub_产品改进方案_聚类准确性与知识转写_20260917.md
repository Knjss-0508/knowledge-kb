## 0. 一句话结论

两条 badcase 的根因已经逐个核对清楚：**它们不是模型写错，而是两条确定性兜底路径把上游字段逐字拼接后输出**（badcase 1 对得上 `_build_topic_source_fact_content` 的四个槽位，含一句写死的内部说明句；badcase 2 对得上 `_structured_knowledge_content` 的默认归档与自动补模板）。所以第一步不是"让模型更聪明"，而是先把这两条路径改成结构化输出。

在此之上，把证据来源改成**分等级字段管线**：第二部分的 AI 分析字段（核心问题 / 判定结论 / 参考话术）升为一级可写证据，会话详情降级为"只用于抽取触发条件与现象的最小事实"，图片视频只做证据不做正文；正文先由**抽取式事实表**生成，模型只负责措辞与排序。先过"不写错"的硬门禁，再谈"写得好"。

## 1. 现状诊断：为什么会写错

### 1.1 证据不分等级，会话详情与人工结论同权

已核对的代码位置：

| 位置 | 现象 |
| --- | --- |
| `workflow.py:4759` `_topic_evidence()` | 只有"完整会话"或"图片证据"才算合格证据，"结构化摘要"不合格。第一道门就偏向会话内容。 |
| `workflow.py:11849` `_topic_source_fact()` | 把 `human_core_problem` / `human_judgment` / `conversation` / `historical_reply` / `judgment_basis` 拼成一个 `fact_text`（11971-11982 行），再用它判断有没有边界。 |
| `workflow.py:12058` `_representative_topic_facts()` | 代表性事实只按"有边界 → 有图片 → 覆盖人工判定结论 → 兜底补充"挑，没有区分证据可写等级。 |
| `workflow.py:14664` `_topic_stage_payload()` | `conversation_evidence` 与整个 `evidence_package` 一起交给模型，会话与结论并列。 |
| `workflow.py:14755` `_topic_reusable_source_values()` | 把上游判定结论、解题方式、语义依据、历史回复、会话证据**拉平成同一个列表**，后续规则无法区分权重。 |
| `mimo.py:995` 转写 Prompt 第 9 条 | 正文"必须提炼来源聊天、历史实际回复或判定结论中的具体信息"——聊天排在第一位。 |
| `mimo.py:996` 第 10 条 | 人工核心问题/判定结论"必须与聊天、历史实际回复共同使用"，是并列而非优先级关系。 |

结论：模型收到的信号里，会话详情是"一等公民"。这与你要求的"弱化会话详情、强化上游 AI 分析"正好相反，所以现状下写错是必然，不是偶发。

### 1.2 两条 badcase 都能对上确定性的后处理路径（已逐个核对）

这条比"模型写错"更重要：**badcase 不是模型幻觉，而是规则兜底路径把上游原始字段逐字拼接后输出的。**

badcase 1 的 4 条与 `_topic_rule_draft()` → `_build_topic_source_fact_content()` → `_template_style_knowledge_content()` 一一对应：

| badcase 1 的第几条 | 数据来自 | 代码位置 |
| --- | --- | --- |
| 1. 回收师在质检中询问"白光有没有问题"… | `适用情形` ← `人工核心问题 or 核心问题`（原样抄） | `workflow.py:13294-13297`、`13329-13330` |
| 2. 屏幕 / 白光检测适用性；后台明确答复"iPhone 13 Pro 不看白光"。；师傅，iPhone 13 Pro 不看白光，这项不用判定 | `核验要点` ← `对象/部位` + `" / "` + `异常现象`，再拼 `判定依据`、`历史实际回复`，用"；"连接（全部原样抄） | `workflow.py:13298-13306`、`13331-13348` |
| 3. iPhone 13 Pro 不看白光，无需针对"白光/白底背光类问题"进行判定 | `处理结论` ← `人工判定结论` | `workflow.py:13349-13350` |
| 4. 仅覆盖上述来源事实明确记录的对象、条件和结论；来源未说明的其他情形不得直接套用，需要补充对应事实后再判断。 | `适用边界` ← **代码里写死的固定句**，被"去前缀"正则剥掉"适用边界："后变成正文的一条 | `workflow.py:13353-13356`（写死）、`13369-13375`（去前缀）、`13494-13495`（调用点） |

也就是说：

1. 该路径把上游字段**逐字拼进正文**，所以"回收师…"这类案例叙述、"师傅，…"这类口播语气必然出现。
2. 第 4 条不是模型编的，是代码注入的内部说明句，而且当前被测试锁定（`tests/test_mimo_workflow.py:10989` 断言"来源未说明的其他情形不得直接套用"必须出现在正文里）；同时 `workflow.py:17433-17438` 又把同类措辞列为可豁免的固定句。也就是说它已被当作"模板噪声"，却仍然留在正文里。改它需要同步改这条断言。
3. 修复这一条是确定性的小改动，不需要模型能力提升。

badcase 2 的形态（1.～6. 编号 + `事实核查结果` + 图片描述）对应的是另一条路径 `_structured_knowledge_content()`（`workflow.py:13860`）：未识别栏目归属的行会默认归入 `判定规则`（`13899`），且当"处理步骤""例外与边界"为空时会自动补通用三步和通用边界（`13927-13940`）。这与 2026-09-11 记录的污染最小复现（markers：回收师、事实核查结果、图片显示、序列号）一致。

结论：两条 badcase 分别落在**两条不同的确定性后处理路径**上，因此"改 Prompt"不解决问题；必须在这两条路径的出口做结构化和拦截。

### 1.3 证据被压成一坨文本，审计证据与可写证据不可分

`fact_text` 是纯文本拼接，层级信息在进证据包那一刻就丢了。质量门禁 `topic_transcription/logic_gate.py` 的 `_fact_refs()` 只用"≥6 字子串重合 或 SequenceMatcher 相似度 ≥0.45"判断"来源支持"。

因此：只要正文里抄了会话原文（例如"回收师在质检中询问…"），就会被判定为"有来源支持"而通过——这正好解释了为什么 1.2 里那种逐字拼接的正文能顺利通过来源校验。

### 1.4 门禁只验"来源支持"，不验"主题纯度 / 视角 / 完整性"

关键原则（与 `reports/topic_transcription_quality_audit_2026-08-06.md` 的结论一致）：

> 有来源支持 ≠ 可以进入知识正文 ≠ 属于当前主题 ≠ 可复用规则

现有 `audit_topic_draft()` 已能拦量词、条件方向、极性、绝对化范围，但**没有**这三类校验：

1. 第三人称案例叙述（回收师/后台人员/会话/聊天记录）
2. 图片与视频描述（第一张图片显示…）
3. 系统元指令泄漏（"仅覆盖上述来源事实明确记录的对象…"）

2026-08-06 报告还记录了两个已知漏点：17 字结论型正文能通过候选校验；规则初审"需修改"会被模型初审"通过"覆盖。

## 2. 上游口径调整（本次最关键的一条）

第二部分 AI 分析准确率已提高，因此把它从"与会话并列"升级为"结构化的可写事实源"，同时明确每个字段的角色。这一步是整个方案的支点。

| 上游字段 | 在产品里的角色 | 允许进入 | 不允许进入 |
| --- | --- | --- | --- |
| 核心问题 | 主题定名、检索问法、主题边界 | 主标题、副标题、关键词、适用范围 | **正文措辞**（该字段通常是案例叙述式，如"回收师在质检…发现…因此咨询后台应如何判定"） |
| 判定结论 | 正文"处理结论"锚点，最高权威可写事实 | 正文结论句、判定依据 | 不得被会话中的猜测或追问替代 |
| 参考话术 | 推荐回复骨架 | 推荐回复 | 正文（话术不是规则） |
| 判定依据 | 结论的支撑，与结论一致时可写 | 正文"判定依据"句 | 不得单独派生新结论 |
| 会话详情 | 仅用于抽取必要的触发条件、现象、动作 | 条件句、现象名、机型/部位名词短语 | 叙述句、说话人、图片描述、内部流程 |
| 图片 / 视频 | 证据，不进正文 | 图例、`image_evidence_summary` | "第一张图片显示…" |

证据等级建议（L0 最高）：

- L0 上游 AI 判定结论 / 参考话术
- L1 人工答疑的判定结论 + 判定依据（答疑人员是权威）
- L2 历史实际回复
- L3 会话详情（只能提取条件/现象/对象的名词短语，不得成句照搬）
- L4 图片 / 视频（只作证据与图例）

规则：

1. L3 / L4 的原文不得直接出现在正文。
2. L0 与 L1 冲突时不静默取一个，直接转人工复核。
3. 每条实质陈述必须能绑定 fact_id + 等级。

好消息：这不是"从零接数据"。`ai_result.py` 已经在解析第二部分 `ai_result` 的 7 个字段，`workflow.py:955` `_apply_ai_result_fields()` 已把它们物化进 `核心问题` / `产品类型` / `判定结论` / `判定依据` / `参考话术`，并且会把与旧字段的冲突写成"ai_result 与已有结构化字段冲突"。要做的是**改权重与通路，不是重新对接**。

## 4. 阶段 A：先不写错（P0）

### A1 证据分层落地

证据包从"扁平文本"改为带等级的结构：`TopicFact` 增加 `layer` 与字段来源，下游（转写、门禁、导出、UI）只认字段，不再读合并后的大文本。

### A2 抽取式正文（extractive-first）

先产出**事实表**：对象 / 条件 / 现象 / 结论 / 边界 / 来源 fact_id + layer。正文只由这张表渲染；模型只能调整措辞与顺序，不能新增事实。字段缺失时写明缺口或转人工，不允许补写。

### A3 视角与格式门禁（新增，确定性规则）

- 正文与推荐回复不得出现：`回收师`、`师傅`、`后台人员`、`答疑人员`、`会话`、`聊天记录`、`图片`、`截图`、`视频`、`事实核查结果`、`来源核验`、`第一张`、`第二张` 等案例指代词（主题本身的对象走白名单）
- 不得出现 Markdown 标记（`*`、`**`、`#`、`|`）
- 不得出现元指令句式："仅覆盖上述…"、"不得直接套用…"、"需要补充对应事实后再判断"
- 不得出现内部分析标签：问题背景、判断对象、来源核验依据、人工处理结论
- 句式必须为规则句式：条件句 + 结论句

同时要改掉两处"结构性生成污染"（这两处不改，门禁只能事后擦，不能治本）：

1. `_build_topic_source_fact_content()` 不得再把 `人工核心问题`、`判定依据`、`历史实际回复` 逐字拼成 `适用情形 / 核验要点`；应改为只输出"对象 + 条件 + 结论 + 边界"四个槽位，且每个槽位必须来自对应来源字段。
2. `workflow.py:13353-13356` 写死的"适用边界"内部说明句必须从正文移除（移到门禁提示或审计字段），并同步修改 `tests/test_mimo_workflow.py:10989` 的断言。

### A4 主题纯度与归属

每条实质陈述必须绑定 fact_id + layer；绑定到 L3 / L4 的内容必须改写成规则句式才允许进正文，否则阻断。

### A5 阻断策略

门禁失败 → 自动重写（复用已有的有界重试机制）→ 仍失败 → 输出"人工复核占位"，而不是半成品正文；候选标"需修改"且不进入可送审集合。**模型初审不得覆盖确定性门禁**（现有设计已如此，需要保持并有测试锁定）。

### A6 顺序修正

门禁清洗放在所有后处理（含图片证据边界追加）之后，并补回归用例锁定。

## 5. 阶段 B：再写得好（P1）

- **content_type 模板化**：定义型 / 阈值型 / 核验型 / 区分型 各自的句式骨架与条数上限。Prompt 已有要求，缺的是渲染层的强约束。
- **标题与副标题**：主标题是一句现场提问；副标题 = 1 条面问法 + 若干点问法（阈值、正反、分支），全部从"核心问题"派生，保证可检索。
- **推荐回复**：以"参考话术"为骨架，补齐对象 + 条件 + 结论三要素，去内部术语，80~180 字。
- **术语与品牌机型**：适用品牌/机型只能来自来源明确字段；单机型事实不得外推为品类规则。
- **可读性（人评）**：一眼能懂、可直接照做、无歧义指代。

## 6. 聚类准确性方案

### 6.1 硬约束（must-link / cannot-link）

已有：产品品类硬门禁、质检标准族、现象值拆分、业务层级。

需要补：

1. 结论极性一致（正常/异常、通过/不通过）
2. 结论对象一致（同一部位或同一功能）
3. 阈值与条件一致（`<1mm` 与 `≥1mm` 不可合并）
4. 适用机型与品牌边界一致（单机型不得并入品类级主题）
5. 标准版本与时间一致

冲突时：不得自动合并，进人工聚类复核；不是直接拆分了事。

### 6.2 评测口径

已有 `scripts/eval_case4_cluster_accuracy.py`：成对 Precision / Recall / F1 + 纯度/覆盖 F1。

需要补：B-cubed F1、ARI，以及错误类型分布（错合并 / 错拆分 / 主题漂移）。**错合并优先下降**，因为它直接污染知识正文。

### 6.3 金集

延续此前的决定：先建 100 条人工金集（≥20% 双人标注），冻结成版本；任何聚类或转写改动先跑金集影子对照，不达标不上线。两条 badcase 与 good case 直接作为首批样本。

### 6.4 上游数据的用法

把 AI 分析的"判定结论"用作聚类的**结论指纹**（极性 + 对象 + 阈值），比纯会话语义更稳；会话只用于消歧（同一现象的不同措辞）。

## 8. 验收指标与上线闸门

先过"不写错"，再谈"写得好"。

不写错（P0，先达标）：

- 事实一致性（100 条金集）：实质陈述被来源支持率 ≥ 99%
- 极性 / 量词 / 条件方向错误：**0 容忍**
- 审计与元信息泄漏率：**0**
- 主题纯度：正文陈述全部属于当前主题，≥ 99%
- 不达标输出必须是"人工复核占位"，不得以半成品进入候选

写得好（P1）：

- 标题可检索性、推荐回复可直接发送率（人评）≥ 90%
- 人工修改率（改动字数/编辑距离）下降

聚类：

- 100 条金集上的成对 F1、B-cubed F1、纯度提升；**错合并率优先下降**

上线闸门：影子双跑（旧/新）→ 盲评 → 金集达标 → 小流量 → 全量。本地通过不等于上线。
