# 主题转写质量只读审查报告

审查日期：2026-08-06
审查范围：当前项目主题级知识转写、内容质量初标、无标准模式字段保留与候选导出链路。
审查性质：只读审查；未修改业务代码。
安全边界：未读取 `data/`、`outputs/`、`.env`，未调用真实 MiMo、CZ、Qwen3 或其他外部服务。

## 一、结论摘要

### 1. “只有结论、无上下文”目前确实可能漏过门禁

当前 Prompt 已明确要求正文包含对象、检查条件、结论和适用边界，但这些主要是**自然语言软约束**。代码层没有把它们转换为不可绕过的结构校验。

一条类似截图中“闭合瞬间的单次异响也属于转轴异响”的 17 字结论型正文：

- 能通过 `mimo.py` 的候选 JSON 校验；
- 不会命中“通用四步模板”检测；
- 规则初标会判“需修改”，但如果 MiMo 内容初审返回“通过”，无标准模式守卫会保留模型的“通过”；
- 10 项候选导出只检查“已经转写且值得沉淀”，不检查最终内容初标是否为“通过”或正文是否具备上下文。

因此，当前问题不是“Prompt 完全没写要求”，而是：

> Prompt 有要求，但确定性门禁没有验证这些要求，模型初审还能覆盖规则初审的短正文判断。

### 2. 无标准模式不会让 MiMo主动生成标准引用，但会原样保留历史字段

当前无标准模式会要求 MiMo 的 `standard_refs=[]`，也会检测模型正文中的标准编号、标准条款和 `【分类】-【路径】` 样式文本。

但是，只要输入行、中间检查点或兼容流程中已经存在 `关联标准项`，系统就会：

1. 从主题成员行合并该值；
2. 写回主题候选的 `关联标准项`；
3. 在 10 项案例知识导出中原样保留。

所以截图中的分类路径式内容更可能来自：

- 历史候选或旧标准模式产物；
- 恢复的中间结果；
- 外部插件或兼容入口写入的字段；
- 人工编辑后重新导入的候选。

它不一定是当前无标准 MiMo 新生成的，但当前代码会把它继续显示和导出，容易让审核人误以为这是当前系统从标准库匹配出的正式关联。

### 3. 截图不太像当前主题主流程的直接产物

截图知识 ID 为 `KB-CASE-0001` 等；当前主题主流程的知识 ID 由
`workflow.py:7631-7633` 生成，格式是 `TOP-XXXXXXXXXX`。

在 `src/`、`tests/` 和 CZ 子项目中未检索到 `KB-CASE-`。

因此不能仅凭截图断言该文件由当前 `build_topic_review_rows()` 直接生成。截图更适合作为问题样例；不过“短结论可漏过门禁”和“分类路径式关联值可被保留”两项问题，已经可以在当前代码中独立复现。

## 二、问题 1：哪些门禁没有拦住“只有结论、无上下文”

## 2.1 转写 Prompt 有要求，但没有结构化输出承载

`src/answer_hub/mimo.py:738-747` 已要求：

- 正文保留 3～5 个必要要点；
- 推荐回复保留具体对象、结论或处理边界；
- 无标准模式至少覆盖以下四项中的两项：
  - 具体对象、代际或来源问题；
  - 检查项或触发条件；
  - 实际结论或处理方式；
  - 不能适用时的边界。

问题是返回 JSON 只有一个自由文本 `content`，没有以下可校验字段：

- `context`;
- `trigger_or_condition`;
- `judgment`;
- `handling`;
- `applicability_boundary`;
- `source_fact_refs`。

因此模型只写最终结论时，程序无法确定它到底缺了哪部分。

## 2.2 MiMo 候选校验只校验字段存在，不校验内容完整性

`src/answer_hub/mimo.py:1704-1758` 的 `_validate_candidate()` 主要检查：

- 必填字段非空；
- 标题不是斜杠关键词堆砌；
- `knowledge_form` 枚举合法；
- `standard_refs` 是数组且引用在允许范围内；
- 置信度在 0～1。

它没有检查：

- 正文最少字数；
- 是否真的有 3～5 个要点；
- 是否同时包含背景、条件、结论和边界；
- 推荐回复是否达到 Prompt 要求的 80～180 字；
- 具体结论是否有来源事实引用。

只读复现实验结果：

```text
validate_candidate= accepted 17
```

即 17 字的“闭合瞬间的单次异响也属于转轴异响。”能通过 MiMo 输出校验。

## 2.3 “通用模板检测”只抓空泛流程，不抓孤立结论

`src/answer_hub/workflow.py:7855-7890` 定义了一批通用流程模板和正则表达式。

`_topic_draft_is_generic()` 在
`src/answer_hub/workflow.py:7966-7982` 只有在：

- 至少命中 3 个通用模板/模式；
- 且没有检测到来源特定内容；

时才判为通用草稿。

截图中的内容不是“补图—核验—再处理”的通用模板，而是直接复述来源结论，因此不会命中。

只读复现实验结果：

```text
generic_detector= False
```

这说明现有检测覆盖了“太空泛”，但没有覆盖“太武断、只有一句结论”。

## 2.4 “来源特定内容”检测过弱，短语重合即可通过

`_topic_draft_has_source_specific_content()` 位于
`src/answer_hub/workflow.py:7929-7963`。

它从聊天、核心问题、语义标注依据和历史回复中切出 3～8 字短语，只要正文命中一个非通用短语就返回 `True`。

这只能证明正文抄到了来源中的某个词组，不能证明正文已经包含：

- 问题背景；
- 判定条件；
- 检查方法；
- 结论；
- 适用边界。

例如正文只复述“属于转轴异响”，也很可能因为与判定结论或聊天存在短语重合而被认定为“有来源特定内容”。

## 2.5 来源短语命中还能绕过“强制降级为流程方法”

`_topic_candidate_row()` 位于
`src/answer_hub/workflow.py:8672-8896`。

`workflow.py:8688-8702` 原本会在证据缺少明确边界时，把“具体判定”强制降级为流程方法。

但无标准模式下，只要
`_topic_draft_has_source_specific_content(candidate, rows)` 返回 `True`，就不会执行该降级。

因此：

> “正文引用了来源中的一句结论”会被等同于“正文具备足够的来源特定知识”，两者当前没有区分。

## 2.6 规则初标能发现正文过短，但模型初标可以覆盖它

`_rule_topic_initial_review()` 位于
`src/answer_hub/workflow.py:8899-8999`。

其中 `workflow.py:8973-8985` 对少于 60 字的正文返回：

```text
decision = 需修改
reason = 知识正文过短，未能完整表达处理规则、步骤或限制条件。
```

问题发生在后续流程：

1. 先计算规则初标，见 `workflow.py:9745-9749`；
2. 如果 MiMo 内容初审可用，模型结果覆盖规则结果，见 `workflow.py:9783-9824`；
3. 再执行 `_apply_topic_initial_review_guard()`；
4. 无标准模式下，该守卫通常只把 `standard_consistency` 改成“无可信标准”，然后直接返回模型结果，见 `workflow.py:9009-9029`。

它没有重新执行“正文少于 60 字”“缺少上下文”“没有边界”等确定性检查。

只读复现实验结果：

```text
rule_review= 需修改
guarded_model_review= 通过
```

这是当前最直接的漏拦截点。

## 2.7 内容质量初标是标签，不是 10 项候选导出的硬门禁

`write_topic_candidate_knowledge_workbook()` 位于
`src/answer_hub/workflow.py:10323-10364`。

当前导出条件只检查：

- `主题转写状态` 不是跳过状态；
- `主题沉淀价值` 是“值得沉淀”。

没有检查：

- `模型初标结论` 是否为“通过”；
- `模型初标内容一致性` 是否为“一致”；
- `模型初标证据充分性` 是否为“充分”；
- 正文是否达到上下文完整性要求。

所以即使规则初标或模型初标标记“需修改”，转写内容仍可能出现在 10 项候选文件中，供人工复核。

这不等于自动发布，但会造成截图中“看起来已经是一条完整知识”的体验。

## 2.8 自动审核依赖模型自报字段，没有独立正文完整性门禁

`src/answer_hub/auto_review.py:121-180` 会检查：

- 模型初标是否为“通过”；
- 证据充分性不是“不足”；
- 内容一致性是“一致”；
- 标题清晰；
- 置信度和模型版本满足要求。

它不会独立解析正文是否包含背景、条件和边界。

现有测试
`tests/test_auto_review.py:72-85` 也表明：无标准模式下，只要模型初标字段符合要求，一条较短的流程正文可以进入自动审核通过集合。

当前生产配置默认关闭自动审核，因此主要风险是“错误内容进入人工候选”；以后启用自动审核前，这会变成实际放行风险。

## 2.9 转写证据仍存在“前 5 条”截断

`_topic_query()` 在
`src/answer_hub/workflow.py:7694-7715` 对核心问题、历史实际回复和判定依据使用 `rows[:5]`。

MiMo 主题输入在 `workflow.py:9561-9579` 对：

- 完整聊天；
- 历史实际回复；
- 判定结论；

也只取前 5 条。

当前没有“代表性案例、冲突案例、例外案例、阈值案例”选择逻辑。

如果第 6 条以后包含反例或适用边界，模型可能只看到一致结论，进而生成没有边界的绝对化知识。

## 三、问题 2：无标准模式为什么仍可能出现分类路径式“关联标准项”

## 3.1 当前模型生成侧实际上禁止新增标准引用

以下代码共同保证无标准 MiMo 不能正常返回新标准引用：

- `mimo.py:714-723`：Prompt 要求 `standard_refs=[]`；
- `mimo.py:3143-3176`：无标准模式允许集合为空，非空引用会被 `_validate_candidate()` 拒绝；
- `workflow.py:9591-9595`：模型正文或其他字段出现标准引用表达时回退；
- `workflow.py:9623-9627`：证据重写后再次检测标准引用；
- `workflow.py:7830-7852`：会检测标准编号、标准条款和 `【...】-【...】` 路径样式。

所以从当前 `label_topic()` 正常返回的 `standard_refs` 看，无标准模式不会主动生成截图中的分类路径。

## 3.2 预处理会保留输入行的额外字段

`preprocess_source_rows()` 在
`src/answer_hub/workflow.py:1616-1706` 首先执行：

```python
row = dict(source_row)
```

之后不会清理额外的 `关联标准项` 字段。

虽然当前正式 `SOURCE_COLUMNS`（`workflow.py:283-303`）不包含 `关联标准项`，但如果输入工作簿、中间检查点或兼容调用直接带入该字段，它会继续存在。

## 3.3 主题候选明确合并并保留已有值

未转写候选：

- `workflow.py:8517-8520` 合并成员行的 `关联标准项`；
- `workflow.py:8601` 写回主题候选。

已转写候选：

- `workflow.py:8711-8714` 合并成员行已有值；
- `workflow.py:8723-8727` 在无标准模式下直接使用该保留值；
- `workflow.py:8860` 写入候选的 `关联标准项`。

所以分类路径一旦进入源行，就会被当作“已有标准关联”继续向后传递。

## 3.4 案例知识导出参数名看似可清理，实际是无操作

`build_case_knowledge_rows()` 位于
`src/answer_hub/workflow.py:10273-10303`。

函数保留了参数：

```python
clear_standard_references: bool = False
```

但 `workflow.py:10278-10281` 明确将其设为兼容参数并忽略：

```python
_ = clear_standard_references
```

随后 `workflow.py:10297` 原样输出：

```python
"关联标准项": _clean_text(row.get("关联标准项"))
```

只读复现实验结果：

```text
preserved_standard_ref= 【其他问题】-【特殊问题】
```

## 3.5 现有测试主动要求这种保留行为

以下测试都把“无标准模式保留已有标准引用”作为当前正确行为：

- `tests/test_mimo_workflow.py:1926-1968`;
- `tests/test_pipeline.py:767-822`;
- `tests/test_pipeline.py:824-836`。

因此这不是偶发遗漏，而是当前明确实现和测试锁定的兼容策略。

## 3.6 为什么看起来像“系统自己生成的分类路径”

当前候选只保留一个 `关联标准项` 展示字段，没有同时展示：

- 该值来自正式标准库检索；
- 该值来自旧候选；
- 该值来自外部插件；
- 该值只是分类路径；
- 该值处于“标准关联搁置”状态。

审核人只能看到 `【显示问题】-【闪屏/花屏】`，无法判断其来源和可信度，于是容易理解为本轮模型生成或标准库匹配。

这是“来源语义混用”问题，不只是字段是否为空的问题。

## 3.7 CZ 送审侧会阻止非空标准关联直接成为无标准候选

`src/answer_hub/cz_integration.py:353-379` 在正式送审校验中规定：

```text
已有标准关联，必须留在标准关联搁置流程，禁止直接送审。
```

`cz_integration.py:441-450` 也要求 `eligible` 必须满足 `not standard_reference`。

因此非空值通常不会被当作合格无标准候选直接送审，但它仍会：

- 出现在本地主题候选和 10 项 Excel 中；
- 出现在 CZ 候选复核原因中；
- 让审核人误以为已经完成了有效标准关联。

## 四、最小可测试的行为验收标准

以下标准只描述可观察行为，不限定具体实现。

## AC-01：结论型正文不得通过内容初标

**给定**

- 无标准模式；
- 来源聊天为“闭合时响了一声，算转轴异响吗？”；
- 人工判定结论为“属于转轴异响”；
- 模型正文只有“闭合瞬间的单次异响也属于转轴异响。”。

**期望**

- 最终 `模型初标结论` 不能是“通过”；
- `模型初标错误类型` 为“话术不合适”或“证据不足”；
- `模型初标重点复核=是`；
- `自动审核状态` 不能是 `auto_approved`；
- 该正文可以保留在审核队列，但不能进入可送审的 10 项候选。

建议测试名：

```text
test_case_only_conclusion_only_draft_cannot_pass_final_quality_guard
```

## AC-02：模型“通过”不能覆盖确定性正文门禁

**给定**

- `_rule_topic_initial_review()` 因正文过短或缺少上下文返回“需修改”；
- MiMo 内容初审返回“通过”。

**期望**

- 最终守卫结果仍为“需修改”；
- 最终原因同时保留确定性门禁原因和模型审核意见。

建议测试名：

```text
test_model_pass_cannot_override_deterministic_content_completeness_failure
```

## AC-03：具体判定必须具备可核验的上下文结构

无标准模式的“具体判定”至少需要覆盖：

1. 具体对象、代际或来源问题；
2. 触发条件、观察事实或检查项；
3. 实际结论和处理方式；
4. 不适用条件、例外或待确认边界。

**最低通过标准**

- 1、2、3 必须存在；
- 4 必须存在，或明确说明“未获得可复用边界，因此只能转为流程方法”；
- 不能只靠字数满足要求。

建议使用结构化字段或事实引用校验，而不是只用关键词计数。

建议测试名：

```text
test_concrete_judgment_requires_context_condition_result_and_boundary
```

## AC-04：每个事实结论必须可追溯到来源记录

模型转写结果至少返回：

```json
{
  "source_fact_refs": [
    {
      "source_record_id": "CASE-001",
      "source_type": "conversation|human_core_problem|human_judgment|historical_reply",
      "fact": "闭合瞬间出现单次异响"
    }
  ]
}
```

**期望**

- 正文中的关键判断至少绑定一个来源记录；
- 找不到来源的事实不得进入正文；
- 只有“最终结论”引用、没有“条件或事实”引用时不能通过。

建议测试名：

```text
test_transcribed_facts_require_source_record_references
```

## AC-05：第 6 条以后的冲突证据不能被静默遗漏

**给定**

- 一个主题有 6 条案例；
- 前 5 条结论一致；
- 第 6 条包含不同代际、例外条件或相反结论。

**期望**

- 转写证据包必须包含第 6 条冲突，或包含明确的冲突摘要；
- 结果必须标记人工重点复核；
- 不得输出无条件的通用结论；
- 代表性证据选择结果应可审计。

建议测试名：

```text
test_representative_evidence_selection_keeps_conflict_beyond_first_five
```

## AC-06：无标准模式的新候选关联标准项必须为空

**给定**

- `use_standard_references=False`；
- 本轮没有加载标准目录；
- 输入没有历史 `关联标准项`。

**期望**

```text
关联标准项 == ""
```

且正文、推荐回复、图片说明不得出现标准编号、标准条款或分类路径式伪标准。

该行为已有部分测试，应继续保留。

## AC-07：已有标准值必须保留审计，但不能伪装成本轮有效关联

**给定**

- 无标准模式；
- 输入带有 `关联标准项=【显示问题】-【闪屏/花屏】`。

**期望**

- 原值不能丢失；
- 原值进入明确的“历史关联/标准关联搁置”审计字段或队列；
- 本轮 10 项候选中的活动 `关联标准项` 为空，或必须同时展示“未验证、禁止送审”的状态；
- `eligible=false`；
- 不得显示成“本轮标准库匹配成功”。

建议测试名：

```text
test_case_only_existing_standard_ref_is_preserved_as_hold_not_active_mapping
```

## AC-08：分类路径不能冒充标准库知识点
