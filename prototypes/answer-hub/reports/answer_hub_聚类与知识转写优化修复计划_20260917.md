# Answer Hub 聚类与知识转写优化修复计划

日期：2026-09-17  
目标：提升聚类准确性，并按照“先不写错，再写得好”的顺序修复知识转写。  
范围：仅规划 `prototypes/answer-hub/**`；本文件不代表已经修改、提交、部署或上线。

---

## 一、最终产品口径

### 1. 知识正文的展示效果

知识正文保持简洁、像标准条款，不采用固定的“适用条件 / 判定规则 / 核验方法 / 适用边界”四段式。

正文规范：

- 通常输出 1～3 条，每条只表达一个可执行结论。
- 优先使用“条件 + 判定结果”或“对象 + 处理规则”句式。
- 只有来源标准明确提供阈值、例外或分支时，才补相应条款。
- 标准未提供的步骤和边界，不为了形式完整而自动补写。
- 品牌、机型、分类、标准来源、证据摘要、推荐回复使用独立字段承载，不在正文反复堆叠。

示例：

```text
1. APP辅助检测手机距离感应功能不通过，但实际通话时靠近耳朵能够正常黑屏的，判定距离感应功能正常。
2. 距离感应功能以实际通话测试结果为准，不以APP辅助工具的单次检测结果直接判定异常。
```

不再生成：

```text
适用条件：……
判定规则：……
核验方法：……
适用边界：……
```

### 2. 内部仍保留结构化校验

前台不展示四段式，不等于后台不做结构化。系统内部仍建立以下事实槽位：

| 内部槽位 | 用途 | 是否直接展示为小标题 |
| --- | --- | --- |
| 对象/部位 | 确认判定对象 | 否，融入正文 |
| 触发条件/现象 | 限定规则成立的条件 | 否，融入正文 |
| 判定结论 | 形成标准式结论 | 否，融入正文 |
| 阈值/例外 | 防止范围扩大 | 仅来源明确时融入正文 |
| 适用品牌/机型 | 限制适用范围 | 否，写独立字段 |
| 标准引用 | 追溯规则来源 | 否，写独立字段 |
| fact_id/证据等级 | 审核和质量门禁 | 否，仅供系统与审核人 |

产品原则：**后台结构化生成和校验，前台简洁标准条款展示。**

## 二、三类转写策略

### 1. 精确命中有效标准

转写策略：**标准为正文主干，上游 AI 分析负责案例与标准的映射，会话只负责核验。**

数据分工：

| 来源 | 主要用途 |
| --- | --- |
| 有效标准正文 | 判定规则、阈值、正反分支、例外与处理优先级 |
| 上游 AI 核心问题 | 标题、检索问法、标准匹配场景、聚类边界 |
| 上游 AI 判定结论 | 校验标准在本案例中的应用结果和正常/异常极性 |
| 上游 AI 参考话术 | 推荐回复骨架 |
| 上游 AI 判定依据 | 补充本案例为何命中该标准 |
| 会话详情 | 核对对象、现象、条件和冲突，不直接复制成正文 |
| 图片/视频 | 证据、图例与审核追溯，不直接描述进正文 |

放行条件：

- 标准状态有效，版本明确；
- 标准召回不是只靠分类路径或模糊关键词；
- 产品类型、对象、现象、关键条件与标准一致；
- 上游判定结论与标准极性一致；
- 标准适用范围覆盖当前品牌/机型，或标准本身不限品牌/机型；
- 不存在阈值、例外或正反条件冲突。

转写限制：模型只能压缩和改写表达，不得改变标准原意，不得删除决定性阈值、量词、否定词、品牌或机型范围。

### 2. 命中标准但存在冲突

以下任一情况直接进入重点人工复核，不生成确定性正式正文：

- 标准判定为异常，上游判定结论为正常，或反之；
- 标准要求“同时满足”，上游字段或会话只支持“任一满足”；
- 标准针对特定机型，当前案例不在适用范围；
- 标准阈值与上游判定依据不同；
- 多个标准得分接近，但结论不同；
- `ai_result` 与已有结构化字段冲突。

审核界面应分别展示“标准规则”“上游 AI 结论”“冲突点”，不得让模型自行选择一个覆盖另一个。

### 3. 未命中可靠标准

分为两类：

- 多条一致、可追溯案例支持：生成“经验知识候选”，正文仅写来源明确的最少结论，强制人工复核。
- 只有单条案例、证据不足或存在冲突：不生成看起来像正式标准的正文，保留候选和证据，标记“证据不足待确认”。

经验候选不得伪装成总部标准，不得生成标准编号、阈值、核验步骤或适用边界。

## 三、数据证据优先级调整

当前问题不是系统完全没有读取上游 AI 字段，而是它们与会话、历史回复被拉平后共同输入转写，权重不清晰。

调整为：

| 等级 | 证据 | 作用 |
| --- | --- | --- |
| L0 | 已确认的有效标准 | 正文规则主干 |
| L1 | 上游 AI 判定结论、核心问题、参考话术、判定依据 | 场景映射和结论核验 |
| L2 | 人工实际回复、人工修订字段 | 补充真实业务口径 |
| L3 | 会话详情 | 提取对象、现象、条件与冲突 |
| L4 | 图片/视频 | 审核证据与图例 |

约束：

- L3、L4 原文不得直接复制进知识正文。
- 核心问题主要用于标题和主题边界；如果它是“回收师在……询问……”式案例叙述，不得进入正文。
- 参考话术只进入推荐回复，不得拼入正文核验要点。
- 上游判定结论与标准冲突时，不能用权重规则静默覆盖，必须人工裁决。
- 每条正文陈述都要绑定来源类型和 fact_id，方便审核追溯。

## 四、分阶段优化修复计划

## P0：先让系统不写错

### P0-1 修复两条确定性污染路径

目标：直接消除当前两类 badcase。

改动点：

1. 修改 `workflow.py` 的 `_build_topic_source_fact_content()`：
   - 不再逐字拼接“人工核心问题 + 判定依据 + 历史实际回复”；
   - 不再输出固定四段式；
   - 不再把参考话术写进知识正文；
   - 删除代码写死的“仅覆盖上述来源事实……”内部说明句；
   - 只根据结构化事实生成 1～3 条标准式规则。
2. 修改 `_template_style_knowledge_content()`：
   - 不再把四个内部槽位机械编号后当成最终正文；
   - 仅对已经通过事实校验的规则句进行编号和格式整理。
3. 修改 `_structured_knowledge_content()`：
   - 未识别内容不得默认全部归入“判定规则”；
   - “回收师、事实核查结果、图片显示”等审计内容直接排除；
   - 缺步骤或边界时不再自动补通用三步和通用边界；
   - 无可靠规则时转人工复核，不输出包装完整的模板正文。

主要文件：

- `src/answer_hub/workflow.py`
- `tests/test_mimo_workflow.py`
- `tests/test_topic_transcription_quality.py`

验收样例：

- iPhone 13 Pro 白光 badcase 最终只保留标准式结论；
- 神舟 BIOS 序列号 badcase 不包含案例叙述、图片描述、事实核查标题；
- 现有距离感应 good case保持 1～2 条简洁规则，不变成四段式。

完成标准：上述 3 条回归测试全部通过，且原有相关测试无回退。

### P0-2 增加最终输出硬门禁

目标：即使上游、模型或新模板再次引入污染，也不能进入候选正文。

门禁类别：

- 案例视角：回收师、后台人员、答疑人员、会话、聊天记录；
- 媒体描述：第一张图片、第二张图片、截图显示、视频显示；
- 审计标签：事实核查结果、来源核验依据、人工处理结论；
- 系统元指令：仅覆盖上述、来源未说明、不得直接套用、补充事实后再判断；
- 格式污染：Markdown 星号、标题符、表格符、残缺标点；
- 逻辑错误：极性反转、量词变化、条件方向改变、无来源范围扩大；
- 主题污染：正文包含当前原子主题之外的对象或结论。

处理方式：

```text
首次失败 → 携带明确失败原因自动重写一次
重写仍失败 → 标记“需修改/人工复核”
               不进入可送审集合
               保留原始草稿和失败原因供审核
```

门禁必须位于所有正文后处理之后，模型初审“通过”不得覆盖确定性失败。

主要文件：

- `src/answer_hub/topic_transcription/contracts.py`
- `src/answer_hub/topic_transcription/evidence.py`
- `src/answer_hub/topic_transcription/logic_gate.py`
- `src/answer_hub/topic_transcription/service.py`
- `src/answer_hub/workflow.py`
- `src/answer_hub/mimo.py`
- `tests/test_topic_transcription_quality.py`
- `tests/test_mimo_workflow.py`

### P0-3 标准参与转写的可靠性门禁

目标：让“有标准参与”真正提高完整性，而不是把不相关标准拼进正文。

实现内容：

- 建立标准适用性检查：品类、对象、现象、条件、阈值、品牌/机型、版本；
- 标准正文与上游 AI 判定结论做极性和条件一致性检查；
- 区分“标准精确命中”“候选标准”“历史关联标准”“分类路径”，只有精确命中允许进入正文；
- 标准内容中的决定性信息转为不可丢失槽位；
- 生成后逐条检查正文是否忠实保留标准的条件和结论。

完成标准：标准错配、标准范围扩大、标准关键阈值丢失均为 0；冲突样例全部进入人工复核。

### P0-4 建立 100 条金集与影子回放

金集覆盖：

- 有标准且结论一致；
- 有标准但极性冲突；
- 有标准但机型/阈值不适用；
- 无标准、多案例一致；
- 无标准、单案例不足；
- 混合图文；
- 纯文本会话；
- 多主题会话；
- 量词、极性、条件方向高风险案例；
- 本次 1 个 good case 和 2 个 badcase。

要求：不少于 20% 样本双人标注；保存输入、期望聚类、标准引用、期望正文、禁止出现内容和人工判定理由。

上线前必须旧/新双跑，不能只看新版本的通过数量。

## P1：再让系统写得好

### P1-1 标准式正文渲染

按知识类型使用轻量句式，不展示固定小标题：

| 类型 | 推荐正文形式 |
| --- | --- |
| 定义型 | “符合……的，属于/不属于……” |
| 判定型 | “当……时，判定为……” |
| 阈值型 | “……达到/未达到……时，按……处理。” |
| 核验型 | “优先通过……核验；结果为……时，判定……” |
| 区分型 | 2～3 条分别描述各分支，不使用大段解释 |

生成规则：

- 标准只有一条明确结论时，只输出一条；
- 标准有正反分支或优先级时，输出 2～3 条；
- 不为凑条数补内容；
- 不将适用品牌/机型在正文中反复重复，除非它是判定规则不可分割的一部分。

### P1-2 标题、副标题和推荐回复

- 主标题：从上游核心问题提炼成一句现场可检索问题；
- 副标题：覆盖常见同义问法、阈值或正反分支；
- 推荐回复：优先采用上游参考话术，核对后只做语气和完整性优化；
- 正文与推荐回复分离：正文像标准，回复像现场答疑；
- 标题、正文、回复必须保持同一对象、范围和结论。

### P1-3 人工复核体验

候选复核页面建议清楚区分：

- 标准式知识正文；
- 推荐回复；
- 命中的标准及版本；
- 上游 AI 核心问题、判定结论和参考话术；
- 脱敏证据摘要；
- 冲突点和门禁失败原因。

不把全部会话默认放在正文旁边争夺注意力；会话详情作为可展开证据。

备注：如需改 CZ 负责的前端或后端，只输出交接需求，不在 Answer Hub 任务中直接修改。

## P2：提升聚类准确性

### P2-1 聚类输入重排

聚类主输入调整为：

```text
产品类型（硬门禁）
→ 上游 AI 核心问题
→ 上游 AI 判定结论（对象 + 极性 + 阈值）
→ 对象/部位与异常现象
→ 标准族/标准适用条件
→ 会话详情用于消歧
```

不再主要依靠长会话文本的整体语义相似度。

### P2-2 必须拆分的硬边界

以下任一项不同，不得自动合并：

- 产品品类或业务层级；
- 对象/部位；
- 判定目标；
- 正常/异常极性；
- 关键阈值；
- 正反条件或例外；
- 品牌/机型适用范围；
- 标准族或标准版本；
- 同一会话中不同原子问题。

模型与硬规则冲突时进入人工聚类复核，不能由模型覆盖硬规则。

### P2-3 聚类评测

继续使用已有：

- 成对 Precision、Recall、F1；
- 纯度、覆盖及其 F1。

补充：

- B-cubed Precision / Recall / F1；
- ARI；
- 错合并率、错拆分率；
- 错误类型分布。

产品优先级：先降低错合并。错拆分会增加人工处理量，错合并会直接把不同事实写进同一条知识，风险更高。

## 六、验收指标与放行门槛

### P0 不写错

- 极性、量词、条件方向错误：0；
- 审计信息、图片描述、系统元指令泄漏：0；
- 标准关键阈值和适用范围丢失：0；
- 标准错配进入正式正文：0；
- 100 条金集的实质陈述来源支持率：≥99%；
- 主题纯度：≥99%；
- 门禁失败样本全部进入人工复核，不得伪装成功。

### P1 写得好

- 正文通常为 1～3 条标准式规则；
- 人工认为“可直接使用或只需轻微修改”的比例：≥90%；
- 推荐回复可直接发送率：≥90%；
- 人工平均修改字数、平均审核时长相对旧版本下降；
- 不以“正文更长”作为质量提升指标。

### P2 聚类

- 在同一冻结金集上比较新旧版本；
- 错合并率必须下降；
- 成对 F1、B-cubed F1 不得下降；
- 低置信、规则冲突和模型失败必须进入人工队列，不能进入转写。

1. `修复知识正文固定模板和审计内容泄漏`
2. `增加标准式正文结构与输出门禁`
3. `调整上游AI字段和会话证据优先级`
4. `增加标准参与转写的一致性校验`
5. `增加聚类硬边界和金集评测`

每个提交只包含本阶段代码和测试，提交前审计暂存文件；不得混入现有工作区其他未提交改动。

## 八、实施顺序和停止条件

推荐顺序：

```text
P0-1 两条确定性路径
→ P0-2 最终输出门禁
→ P0-3 标准参与转写
→ P0-4 100条金集影子回放
→ P1 表达质量
→ P2 聚类准确性持续优化
```

停止条件：

- P0 任一“0 容忍”指标未满足，不进入 P1，也不发布；
- 标准错配率未归零，不允许扩大自动转写范围；
- 金集只提升通过数量、但事实错误增加，立即停止并回滚方案；
- 影子回放不能证明提升时，保持人工复核，不切换主链路；
