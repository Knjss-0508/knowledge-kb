## 二、为什么之前看起来下降

最后一次全新真实 MiMo 的原始结果综合 F1 为 **78.17%**。这是模型原始聚类加当时 v6 后处理的结果，不是当前最终生产版本。

下降主要来自模型输出波动：

- 同一批业务数据，不同真实调用会生成不同的原子拆分和聚类边界。
- 笔记本型号、配置、屏幕现象等大主题容易被拆散。
- 少量大簇会混入相近但不同的人工主题。

当前通过确定性的本地边界规则、明确多主题拆分和离线二次归并，把最后一次真实输出提升到 **80.16%**。因此真实业务应以“MiMo 输出 + 当前程序后处理”的完整结果作为上线指标，不能只看模型原始输出。

## 四、round9 改进内容

### 1. 明确多主题本地拆分

对聊天中明确同时存在两个独立业务目标、但模型只生成一个原子问题的情况，增加四类保守拆分：

- 序列号乱码 + 屏幕碎裂
- 笔记本色斑 + 屏幕表面印记
- 镜头进灰异物 + 消光漆脱落
- 笔记本型号 + 出厂屏幕膜

拆分结果会进入人工优先复核，不直接自动放行。

### 2. 十品类规则随程序发布

此前运行时默认读取：

`data/quality_clustering_rules_10_categories.json`

但 `data/` 按安全要求不会进入 GitHub 发布目录或交付包，可能造成线上退回较弱的内置规则。现已把同一份规则固化到：

`src/answer_hub/quality_clustering_rules_10_categories.json`

程序默认读取随包规则，仍允许通过 `ANSWER_HUB_QUALITY_CLUSTERING_RULES_PATH` 指定受控覆盖文件。

### 3. 跨品类双重硬门禁

- 原子提取和聚类批次按源数据产品类型隔离。
- 模型返回不属于当前批次的原子 ID 时，程序直接忽略并记录计数。
- 最终多成员簇再次检查原子行产品类型。
- 准确率报告新增 `cross_product_cluster_count`，只要大于 0 即视为业务红线失败。

### 4. 不降低全局阈值

本轮没有通过整体放宽相似度来追求分数，避免把不同判定对象、不同现象或不同品类错误合并。

## 五、当前主要问题

### 1. 笔记本仍是主要短板

最新真实缓存回放：

- 笔记本综合 F1：75.93%
- 手机综合 F1：77.79%
- 相机机身综合 F1：83.54%

全局超过 80% 依赖其他品类的较好表现。下一轮优化应优先处理笔记本型号、配置属性和屏幕现象边界。

### 2. 成对 F1 仍偏低

最新缓存成对 F1 为 41.54%。这表示大主题中仍有较多错误拆分和错误合并。综合 F1 达标不代表所有簇已经适合无人审核。

### 3. 上线余量较小

最弱缓存只有 80.16%。模型轻微波动就可能再次低于 80%，因此初版上线必须保留人工审核和监控，不能启用自动发布。

## 六、上线建议

初版采用以下门禁：

1. 只创建 CZ 待审核候选，不自动发布知识。
2. `AUTO_REVIEW_ENABLED` 保持关闭。
3. 不绕过 Qwen3 重复检测和 CZ 终审。
4. 每批记录综合 F1、品类 F1、跨品类簇数、模型降级率和耗时。
5. 跨品类簇必须为 0。
6. 低置信度、多主题救援、模型降级和风险候选进入人工优先审核。
7. 新增人工标注达到一定数量后，再重新评估是否提高到 82% 至 85% 的正式门槛。
