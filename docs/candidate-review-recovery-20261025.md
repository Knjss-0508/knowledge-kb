# 候选复核状态与推荐回复恢复

适用：人工选择“值得沉淀”后仍停留人工待复核、原已自动准入的模型通过候选回退，以及历史草稿推荐回复为空。

## 修复后的规则

- 单项保存“值得沉淀”会同步兼容旧的可用性与审核结论字段；请求明确传入的驳回或不可用结论仍保留。
- 原已自动准入的候选，当前模型初标通过、值得沉淀、置信度达到 `AUTO_REVIEW_MIN_CONFIDENCE`（默认 0.85）、无风险且草稿完整时可进入可批量送审。仅模型建议通过不等于获得自动准入。
- 原始准入与当前送审资格分开保存。历史记录只有明确的 `自动审核：auto_approved` 审计标记才能补回丢失的原始准入；显式撤销优先。修订后的草稿、过期初标、风险和人工否决仍受原门禁限制。
- 没有初标的自动准入候选也必须有达到阈值的上游置信度；缺失、非法或低置信度不能依赖历史标记放行。
- 推荐回复复用完整且有据的正文时，不再仅因“复述正文”被清空。主题偏移、缺少依据、不完整句子等原校验仍保留。

## 既有候选状态

更新代码不会自动扫描或改写全库。人工候选可打开并重新保存复核结论；需要按历史审计标记恢复状态的记录可使用定向脚本。

在已配置数据库连接的后端运行环境中执行，凭据使用该环境现有配置，不写进命令。以下 `候选ID` 需替换为待核对的真实 ID：

```bash
python -m app.scripts.repair_candidate_review_states --ingestion-id 候选ID
```

默认只计算预览并回滚，输出原状态、目标状态与阻断原因。一次最多指定 100 个不同 ID，可重复传 `--ingestion-id`。不存在、Excel 来源及已送审锁定记录跳过。

核对预览后，确需写入时执行：

```bash
python -m app.scripts.repair_candidate_review_states --ingestion-id 候选ID --apply
```

写入时锁定所选记录、重新计算并统一提交。脚本只更新候选状态及其审计元数据，不补造人工真值、不生成正文或回复、不提交发布审核。没有明确准入证据的候选继续人工复核；旧的人工字段不一致可通过重新保存结论修复。

## 既有草稿缺少推荐回复

1. 打开候选复核详情，保存标题、正文和**来源证据摘要**。“保存审核”允许保存未完整草稿，包括已确认值得沉淀但缺回复的记录；“保存并送审”仍要求完整。
2. 点击“执行模型标注”，也可批量选择后执行“批量模型标注”。缺回复时，初标先依据已保存的来源证据摘要补回复，再审核补齐后的草稿。已有回复不覆盖，正文和媒体不改动。
3. 生成结果必须带可核对的摘要原文依据。标题仅限定问题范围，不能把无依据的正文或其他会话当作补充事实；摘要不足、回复为空或模型调用失败时记录原因，补证据后可重试。
4. 补回复会生成新的草稿版本并保留原稿和摘要快照，初标绑定补齐后的版本；原人工价值确认仍保留在历史版本，需要重新确认当前版本，门禁通过后再送审。不会自动发布知识。

没有来源证据摘要的空回复草稿先补摘要；缺标题或正文的草稿先补齐再初标。回复本来完整的草稿仍可在摘要为空时初标，模型可判定待补证据。已送审候选不能重新初标。

若补回复成功但随后初标失败，已生成回复与草稿版本仍保留，页面重新读取已保存结果；重试只执行初标，不重复补回复。页面读取失败时暂时阻止保存旧表单，重新打开会再次读取服务端详情，避免旧空值覆盖模型补充。

## 验证边界

回归验证使用合成候选、模拟模型与独立 SQLite 数据库，覆盖默认预览回滚、显式写入范围、初标补回复与版本失效。真实模型质量、生产候选分布及线上页面仍需在相应环境验收；本次本地修复不执行生产数据修复。
