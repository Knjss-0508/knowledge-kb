# 候选模型自动处理

本次基于主分支 `e8821228e34310a2bd802662cedc67e6fdcbc51d`，包含曼哈顿品类白名单及旧缓存修复，同时修复候选回收业务分类和批量请求执行方式。

## 回收业务分类

十二品类为手机、平板电脑、智能手表、耳机/耳麦、笔记本、游戏机、游戏卡带、单电/微单机身、单反机身、相机镜头、手写笔、学习机。

有明确产品证据且属于十二品类之外的候选归为聚合回收，覆盖旧的自营默认值。来源结构化品类优先，旧值只作审计。品类占位值不遮蔽后续明确产品；类别对象中的名称、业务路径、常用品类别名和复合产品字符串均可识别。内部类别 ID 不被当成产品名称。十二品类已有明确的聚合业务记录继续保留。

Answer Hub 在预处理及业务层级映射时应用该规则；主站在候选接收、详情读取、模型处理和送审时应用该规则。不凭标题中的设备词猜测产品，也不批量改写已进入知识库管理的历史知识。

## 页面操作

在“候选价值复核”勾选“自动模型标注并送审”，服务端会扫描已有及后续新增的未人工复核候选，每批最多 100 条、逐条处理。处理状态包含待人工确认、待模型初标、退回转写和已可送审；待补证据、不沉淀、已人工复核和已送审的候选不被自动扫描。

手动选择 20、50、100 条点击“批量模型标注并送审”同样创建持久化后台任务。创建请求返回 HTTP 202，不等待模型完成，关闭页面后继续处理。

自动处理区默认折叠为状态栏，仅保留自动开关、当前任务进度、有失败的任务数和查看入口。服务暂停和接口错误即使折叠也保持可见。展开默认查看“有失败”，可切换全部历史，每页 10 条紧凑表格；逐条结果在点击“明细”或“重试失败项”时单独获取。折叠时只请求状态摘要，不返回历史列表或逐条结果；处理中每 5 秒刷新，空闲或保护性暂停时每 15 秒刷新数据库状态，不调用模型网关探测健康状态。

流程复用候选创建时间对应的已批准 Prompt，允许一次模型修订，再次初标，通过原有置信度和风险门禁后执行查重，最终只进入知识库待审核。权限失效会停止任务。自动开关默认关闭；关闭后当前条完成，后续自动条目停止，手动任务不受影响。

同一草稿版本的自动尝试只执行一次，手动批量模型处理也写入该草稿的已尝试标记，避免手动失败项被后续自动扫描再次捞起。失败后可以手动重试；修改草稿生成新版本后可再次自动处理。单条失败保留结果并继续下一条；连续服务故障遵循下述暂停保护。已记录结果不会重复执行。进程中断的当前条保留已保存内容、标记中断供人工检查重试，后续候选继续；不会因恢复重复采用修订。

## 模型网络异常处理

补充推荐回复、模型初标和草稿修订的单次模型调用，遇到可重试的断连、超时、HTTP 429 或服务端错误时，最多尝试 3 次，两次重试前分别等待 2 秒、5 秒。同一进程内的候选模型请求串行执行，每次请求结束后等待 1.05 秒，避免同一候选内部连续请求。该间隔不限制其他模型业务或其他进程；后台候选任务仍由原有 PostgreSQL 锁串行调度。

重试仅发生在模型调用阶段，不重复采用修订、写入草稿或送审。鉴权、配置、非法输出、证据不足和内容门禁错误不通过重试放行。错误提示包含异常类别与尝试次数，不包含原始连接地址或鉴权信息。

连续两条候选在有限重试后仍出现断连、超时、HTTP 429 或 HTTP 5xx 时，持久化暂停全部后台候选任务；配置缺失或 HTTP 401/403 立即暂停。修订后的重新初标同样保留服务错误类别并参与判断。业务门禁、证据和模型输出错误不触发服务暂停。暂停状态跨 worker 轮询和应用重启保留，不自动恢复、不自动探测网关、不自动重排失败项；关闭或重新开启自动开关也不会清除保护状态。

确认网关恢复后点击“确认网关恢复，继续处理”解除保护，恢复仅继续尚未处理的候选，保持自动开关原值。已失败候选保留人工处理，通过原任务的“重试失败项”手动重试。前两条失败保留各自结果，后续未处理候选不计失败、不消耗该草稿的自动尝试次数。

旧的同步批量接口保留兼容入口，与后台 worker 共用 PostgreSQL 会话级候选执行锁；已有候选执行者时立即返回 HTTP 409，不新增并发模型负载。同样逐条检查保护状态并累计服务故障；达到阈值后立即停止，返回 HTTP 503 说明处理数量及剩余条目尚未执行，暂停时再次调用返回 HTTP 409。推荐使用持久化后台任务接口查看完整进度与失败明细。

这些保护限制本应用的候选处理负载，不修改、重启组内网关或 SSH 隧道。其他应用负载、组内电脑休眠、网络变化和隧道自身故障仍需在相应运行环境排查，不能通过应用测试保证网关永不断开。

页面将“流程失败”和“送审失败”分别显示。“标注成功”表示模型流程完成，不代表送审成功；这些候选中仍可能有送审失败项，不能将标注成功与送审失败直接相加作为候选总数。

## 数据库升级

新增迁移 `20261027_01_candidate_tasks`，父节点为当前迁移头 `20261013_01_hf_persist`。新增任务表、自动设置表和默认关闭的设置记录，不改写历史候选。

保护性暂停另有迁移 `20261028_01_candidate_pause`，接在已部署的 `20261029_01_candidate_jsonb` 之后，避免与候选 JSONB 迁移分叉。为自动设置表增加连续故障计数、暂停时间和原因，已有自动开关和任务进度保持原值。发布新后端前必须执行此迁移。

在已确认的部署环境先备份数据库，随后按项目现有发布流程执行迁移：

```powershell
Set-Location backend
python -m alembic upgrade head
```

后端启动时运行任务 worker。PostgreSQL 会话级 advisory lock 保证同一时间只有一个模型任务执行者；租约用于进程退出后的恢复。任务表记录当前执行候选，避免恢复时再次修改已经提交的草稿。

上线需要同时交付后端、前端和 Answer Hub 的分类改动。本说明不代表已创建 PR、已部署或已开启生产自动处理。
